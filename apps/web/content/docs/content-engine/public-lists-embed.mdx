---
title: Add a list to another page
description: Show a VitNode Content Engine public list inside any page or component, with your own item layout, using contentListQueryOptions and ContentListResults.
icon: PanelsTopLeft
---

A list does not need its own route. The same query options that feed `/blog` can fill a "Latest articles" box on a home page, a sidebar or another plugin's page, rendered however that page needs. This guide reuses the blog's query from [Public lists](/docs/content-engine/public-lists) and draws each article as a compact row instead of a card.

<Steps>

<Step>

### Render the list with your own items

Call the list's query options with `useQuery` and hand the rows to `ContentListResults`. `renderItem` receives each row exactly as the query returned it, so nothing is article-shaped unless you make it so:

```tsx title="src/components/latest-articles.tsx"
import { useQuery } from '@tanstack/react-query'
import { blogPostHref } from '@vitnode/blog/pages/blog-card'
import { blogPostsQueryOptions } from '@vitnode/blog/pages/blog-queries'
import { ContentListResults } from '@vitnode/core/tanstack/content'
import { HrefLink } from '@vitnode/core/tanstack/link'
import { useLocale } from 'use-intl'

export const LatestArticles = () => {
  const locale = useLocale()
  const { data, isError, isFetching } = useQuery(
    blogPostsQueryOptions({ locale, search: {} }),
  )

  return (
    <section aria-labelledby="latest-articles" className="flex flex-col gap-3">
      <h2 className="text-lg font-semibold" id="latest-articles">
        Latest articles
      </h2>
      <ContentListResults
        className="flex flex-col divide-y rounded-xl border"
        empty={<p className="text-muted-foreground text-sm">Nothing yet.</p>}
        error={
          <p className="text-muted-foreground text-sm">
            Could not load articles.
          </p>
        }
        getKey={(post) => post.id}
        isError={isError}
        isFetching={isFetching}
        isFiltered={false}
        itemClassName="p-3"
        items={data?.edges.slice(0, 5)}
        label="Latest articles"
        loading={<p className="text-muted-foreground text-sm">Loading...</p>}
        noResults={null}
        renderItem={(post) => (
          <HrefLink
            className="font-medium hover:underline"
            href={blogPostHref(post.friendlyUrl)}
          >
            {post.title}
          </HrefLink>
        )}
      />
    </section>
  )
}
```

Translate the strings through your own locale namespace in real code. They are inline here to keep the example short.

</Step>

<Step>

### Render it on the server too

`useQuery` does not fetch during SSR, so the box starts as `loading`. To send it with the HTML, warm the same options in the host route's loader. Leave out `LOADER_DATA_QUERY_META`, so the query is dehydrated and `useQuery` finds it in the browser:

```ts title="src/pages/home-page.tsx"
import { blogPostsQueryOptions } from '@vitnode/blog/pages/blog-queries'
import { defineRoute } from '@vitnode/core/tanstack/plugin-routes'

export const route = defineRoute({
  load: async ({ context }) => {
    await context.queryClient.query(
      blogPostsQueryOptions({ locale: context.locale, search: {} }),
    )
  },
})
```

Both calls build the same key, `["@vitnode/blog", "posts", { locale }]` - the same one the first page of `/blog` uses - so they share one cache entry, and a later `invalidateQueries({ queryKey: ["@vitnode/blog", "posts"] })` refreshes the box together with `/blog`.

</Step>

</Steps>

## Check the result

Open the page that renders `<LatestArticles />` and view its source: the article titles are in the HTML. Publish an article in **AdminCP → Blog → Articles** and reload the page: it appears at the top. An empty `search` is the plain list, newest first.

## Use a different list shape

The blog's list shows 12 rows a page. For a box that needs a different page size, sort or filter set, declare a second list with [`defineContentList`](/docs/content-engine/public-lists-api#definecontentlist) and its own query options. Keep the same `queryKey` prefix, such as `["@vitnode/blog", "posts"]`, so one invalidation still covers both.
