`publication` gives every record two states, **Draft** and **Published**. Drafts stay private, and only staff with the publish permission make a record public. Turn it on before anything reaches readers, because the [public API](/docs/content-engine/public-api) only ever returns published records.

This continues the `newsroom.article` type from [First content type](/docs/content-engine/create-a-content-type).

<Steps>

<Step>

### Turn on publication

Edit `src/content/article.ts`. Add `publication` and show the state in the list:

```ts title="plugins/newsroom/src/content/article.ts"
export const articleContentType = defineContentType({
  id: "newsroom.article",
  tableName: "newsroom_articles",

  fields: {
    title: field.text({ required: true, minLength: 3, maxLength: 200 }),
    slug: field.slug({ source: "title" }),
    body: field.richText({ required: true }),
  },

  publication: true, // [!code ++]

  admin: {
    path: "newsroom/articles",
    titleField: "title",
    list: {
      columns: ["status", "title", "slug", "updatedAt"], // [!code highlight]
      orderableFields: ["title"],
    },
  },
});
```

This adds a `status` column (`draft` or `published`), a `publishedAt` date, a `can_publish` staff permission, and **Publish** and **Unpublish** actions in the AdminCP.

</Step>

<Step>

### Label the new permission and column

Add two keys to `src/locales/en.json`. This excerpt shows only the new keys, in their place:

```json title="plugins/newsroom/src/locales/en.json"
{
  "newsroom": {
    "content": {
      "article": {
        "fields": {
          "status": "Status"
        }
      }
    }
  },
  "newsroom:article:can_publish": "Publish and unpublish articles"
}
```

</Step>

<Step>

### Migrate

Run this from the workspace root while `pnpm dev` is running, or after `pnpm build:plugins`:

<Tabs groupId="package-manager" persist items={["bun", "pnpm", "npm"]} label="Migrate the database">

```bash tab="bun"
bun run db:migrate
```

```bash tab="pnpm"
pnpm db:migrate
```

```bash tab="npm"
npm run db:migrate
```

</Tabs>

The migration adds `status`, with `draft` as its default, and `publishedAt`. Both articles you already created are now drafts.

</Step>

<Step>

### Publish an article

Open **AdminCP → Newsroom → Articles**. Both rows show **Draft**. Click the paper plane button in the `Welcome to the newsroom` row:

<ImgDocs
  withoutBackground
  className="*:max-w-full"
  src={publishRow}
  alt="Newsroom Articles list with two Draft articles and the Publish tooltip over the paper plane button"
/>

Confirm with **Yes, publish it**:

<ImgDocs
  src={publishConfirm}
  alt="Publish Article dialog asking to publish Welcome to the newsroom, with Cancel and Yes, publish it"
/>

Leave `Release notes for October` as a draft. The next tutorial checks that readers cannot see it.

</Step>

</Steps>

## Check the result

The list shows **Published** for one article and **Draft** for the other, and a **Status** filter appears above it. The create dialog now has **Save as draft** and **Publish** buttons, and [bulk actions](/docs/content-engine/admincp#bulk-actions) publish many rows at once.

| The record is | Readers get |
| --- | --- |
| A draft | Nothing; the public API answers `404`, the same as a slug that never existed |
| Published with a future `publishedAt` | `404` until that moment |
| Published | The record |

To publish on a schedule, or share a draft before it goes live, see [Scheduling](/docs/content-engine/editorial-scheduling) and [Previews](/docs/content-engine/editorial-previews).
