`publicApi` gives a content type read-only routes anyone can call: a list and a single record. They return only published records, and only the fields you name. Your pages read these routes; nothing about a content type is public until you add them.

This continues the article from [Drafts & publishing](/docs/content-engine/publication): one published article, `Welcome to the newsroom`, and one draft, `Release notes for October`.

<Steps>

<Step>

### Choose the public fields

Edit `src/content/article.ts` and add `publicApi` after `publication`:

```ts title="plugins/newsroom/src/content/article.ts"
  publication: true,

  // [!code ++:4]
  publicApi: {
    path: "news",
    fields: ["id", "title", "slug", "body", "publishedAt"],
  },
```

- `path` becomes part of the URL, `/api/newsroom/content/news`, and the module name your pages use, `content/news`. Pick one no other plugin in the app uses, because [content pages](/docs/content-engine/public-pages) turn it into a site-wide URL.
- `fields` has no wildcard. A field you add later stays private until you list it here.
- Exactly one slug field must be listed, because the single-record route finds records by it.

</Step>

<Step>

### Register the public routes

Edit `src/config.api.ts` and add the model to `buildContentPublicModule`. This is an excerpt:

```ts title="plugins/newsroom/src/config.api.ts"
import { buildContentPublicModule } from "@/api/builders"; // [!code ++]
import { articleContent } from "@/database/articles"; // [!code ++]
import { manifest } from "@/manifest.gen";

import { adminModule } from "./api/modules/admin/admin.module";
import { helloModule } from "./api/modules/hello/hello.module";

export const newsroomApiPlugin = () =>
  buildApiPlugin({
    manifest,
    modules: [
      helloModule,
      adminModule,
      buildContentPublicModule({ contentTypes: [articleContent] }), // [!code ++]
    ],
  });
```

`publicApi` adds no columns, so there is nothing to migrate. `pnpm dev` serves the routes as soon as it rebuilds.

</Step>

</Steps>

Only the published article is in `edges`, with exactly the five listed fields. Now ask for each article by slug:


## Read it from a page

Pages call these routes with the [fetcher](/docs/dev/fetcher). The module is `content/` plus `path`; the route, its parameters and its response are typed from your definition:

```ts
import { fetcher } from "@vitnode/core/tanstack/fetcher";

import { manifest } from "@/manifest.gen";

const res = await fetcher({
  plugin: manifest.id,
  method: "get",
  module: "content/news",
  path: "/{slug}",
  args: { params: { slug: encodeURIComponent(slug) } },
});
```

A field you did not list, or a module that does not exist, is a compile error. The list route also takes `first` (up to 50), `page` or `cursor`, `search`, `orderBy` and `order`; [List API](/docs/content-engine/public-lists-api) has every parameter, and [Search](/docs/content-engine/public-lists#add-search) shows which options turn them on.
