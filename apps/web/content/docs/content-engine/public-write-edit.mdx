This page builds `/news/:id/edit`, where an article's author, or a moderator, changes it. The page loads what may be edited, saves with the version it opened, and keeps the member's text when something goes wrong.

This continues the [Create form](/docs/content-engine/public-write-frontend). It reuses `ArticleForm` from `src/pages/article-form.tsx`, and needs `editorial: true` from [Member writing](/docs/content-engine/public-write), which gives every article a `version`.

## Three kinds of values

An edit page handles three different things. Keep them apart, or a member will think a change is live when it is not:

| What | Where it comes from | Readers see it |
| --- | --- | --- |
| **Live values** | `record.values` from `GET /{id}/edit` and `PATCH /{id}` | Yes |
| **Proposed values** | `record.approval.values`, when `approval.status` is `"pending"` and `approval.kind` is `"edit"` | No, until a moderator approves |
| **A save that changes nothing public yet** | `PATCH /{id}` answers `200` with `approval.status: "pending"` | No. `values` is still the live record |

The last two only happen in a container whose [publishing rules](/docs/content-engine/container-policies) say `edits: "approve"`. Newsroom articles have no containers, so for them a `200` always means the change is live. The page still handles both, so it keeps working when you add rules later.

### Load the editable values

Create `src/pages/article-edit-page.tsx`. Its first part loads the article. `GET /{id}/edit` answers only for the author and moderators, drafts included:

```tsx title="plugins/newsroom/src/pages/article-edit-page.tsx (excerpt)"
// Answers only for the author and moderators, drafts included.
const fetchEditableArticle = async (id: number) =>
  await fetcher({
    plugin: manifest.id,
    method: "get",
    module: "content/news",
    path: "/{id}/edit",
    args: { params: { id } },
  });

const loadEditableArticle = async (param: string) => {
  const id = Number(param);
  if (!Number.isSafeInteger(id) || id < 1)
    return { state: "notFound" as const };

  const res = await fetchEditableArticle(id);
  if (res.status === 200) {
    return { record: await res.json(), state: "ready" as const };
  }
  if (res.status === 401) return { id, state: "unauthenticated" as const };
  if (res.status === 403) return { state: "forbidden" as const };
  if (res.status === 404) return { state: "notFound" as const };

  // A server failure is not "not found": let the app's error page show it.
  throw new Error(`Loading article ${id} for editing failed.`);
};

type ArticleEditData = Awaited<ReturnType<typeof loadEditableArticle>>;

type EditableArticle = Extract<ArticleEditData, { state: "ready" }>["record"];

export const route = definePluginRoute({
  load: async ({ params }) => await loadEditableArticle(params.id),

  head: ({ t }) => ({
    robots: "noindex, nofollow",
    title: t("newsroom.articles.edit.title"),
  }),
});
```

Each answer becomes its own page state:

- `401`: the visitor is signed out. Show a sign-in link that comes back here.
- `403`: they can read the article but may not edit it.
- `404`: it does not exist, or it is a draft or hidden article that is not theirs. The page never confirms it exists.
- Anything else is thrown, so a server failure shows the app's error page instead of "not found".

</Step>

<Step>

### Save changes

Between the loader and the page component goes `ArticleEditForm`. It fills `ArticleForm`, sends `PATCH /{id}` with the version, and handles the answer:

```tsx title="plugins/newsroom/src/pages/article-edit-page.tsx (excerpt)"
const ArticleEditForm = ({ record }: { record: EditableArticle }) => {
  const t = useTranslations("newsroom.articles.edit");
  const queryClient = useQueryClient();
  const [current, setCurrent] = useState({
    approval: record.approval,
    slug: record.slug,
    status: record.status,
  });
  // AutoForm resets an untouched form to the defaults it renders with, so the
  // defaults follow every save.
  const [defaults, setDefaults] = useState(() => formValuesOf(record));
  const write = useContentPublicWrite({
    fields: ARTICLE_FORM_FIELDS,
    latestVersion: async () => {
      const res = await fetchEditableArticle(record.id);

      return res.status === 200 ? (await res.json()).version : null;
    },
    uniqueField: "title",
    version: record.version,
  });

  const onSubmit: AutoFormOnSubmit<ArticleFormSchema> = async (
    values,
    form,
  ) => {
    const updated = await write.submit(
      form,
      async expectedVersion =>
        await fetcher({
          plugin: manifest.id,
          method: "patch",
          module: "content/news",
          path: "/{id}",
          args: {
            params: { id: record.id },
            body: { values, expectedVersion },
          },
        }),
    );
    if (!updated) return;

    setCurrent({
      approval: updated.approval,
      slug: updated.slug,
      status: updated.status,
    });
    setDefaults(values);
    form.reset(values);
    await queryClient.invalidateQueries({
      queryKey: [manifest.id, "articles"],
    });

    if (updated.approval?.status === "pending") {
      toast.info(t("pending.title"), { description: t("pending.desc") });
    } else {
      toast.success(t("success.title"), {
        description: t("success.desc", { title: values.title }),
      });
    }
  };

  return (
    <>
      <ApprovalNotice approval={current.approval} />
      {write.conflict}
      <ArticleForm
        defaultValues={defaults}
        onSubmit={onSubmit}
        submitLabel={t("submit")}
      />
      {current.status === "published" && current.slug !== null ? (
        <HrefLink
          className={buttonVariants({
            className: "self-start",
            variant: "link",
          })}
          href={`/news/${current.slug}`}
        >
          {t("view")}
        </HrefLink>
      ) : null}
    </>
  );
};
```

- **`useContentPublicWrite`** gets the `version` the form opened with and passes it to `request` as `expectedVersion`. After a save it stores the new version itself.
- **`write.submit`** returns the record, or `null` after showing the reason: a field error, a taken title under **Title**, or a toast for the rest, such as an expired session.
- **After a save**, the page keeps `approval`, `slug` and `status` from the answer, moves the form's defaults to the saved values, resets the form so it is no longer dirty, refreshes the cached article list and picks the toast. `defaults` lives in state because `AutoForm` resets an untouched form to the `defaultValues` it renders with; without `setDefaults(values)`, the old text would come back after a successful save.
- **View article** links to the public page while the article is published. The slug comes from the latest answer.

</Step>

<Step>

### Handle version conflicts

Nothing extra to write: `write.conflict`, rendered above the form, is the conflict alert. When someone else saved after the form opened, `PATCH /{id}` answers `409 CONTENT_VERSION_CONFLICT`, writes nothing, and the alert appears while the form keeps every character the member typed:

- **Keep my version** reads the current version with `latestVersion`. The next **Save changes** replaces the other change.
- **Load latest version** reloads the page and drops the unsaved text.

</Step>

<Step>

### Handle pending proposals

The last two pieces open a pending edit on the proposal and say what is happening. Put them between the loader and `ArticleEditForm`:

```tsx title="plugins/newsroom/src/pages/article-edit-page.tsx (excerpt)"
const zodProposal = z
  .object({
    body: zodRichTextDocument.optional(),
    title: z.string().optional(),
  })
  .catch({});

/** A pending edit opens on what the author proposed, not on the live text. */
const formValuesOf = (record: EditableArticle): ArticleFormValues => {
  const { approval } = record;
  const proposed =
    approval?.status === "pending" && approval.kind === "edit"
      ? zodProposal.parse(approval.values ?? {})
      : {};

  return {
    body: proposed.body ?? record.values.body,
    title: proposed.title ?? record.values.title,
  };
};

const ApprovalNotice = ({
  approval,
}: {
  approval: null | Pick<ContentApprovalState, "kind" | "reason" | "status">;
}) => {
  const t = useTranslations("newsroom.articles.approval");

  if (approval?.status === "rejected") {
    return (
      <Alert variant="destructive">
        <AlertTitle>{t("rejected.title")}</AlertTitle>
        <AlertDescription>
          {approval.reason
            ? t("rejected.reason", { reason: approval.reason })
            : t("rejected.desc")}
        </AlertDescription>
      </Alert>
    );
  }

  if (approval?.status === "pending") {
    const key = approval.kind === "edit" ? "pending_edit" : "pending_create";

    return (
      <Alert variant="info">
        <AlertTitle>{t(`${key}.title`)}</AlertTitle>
        <AlertDescription>{t(`${key}.desc`)}</AlertDescription>
      </Alert>
    );
  }

  return null;
};
```

`approval.values` is untyped, so `zodProposal` reads the fields it knows and ignores the rest. The notice covers a rejected submission with the moderator's reason, a pending edit and a pending new article.

</Step>

## When edits wait for a moderator

Articles in this tutorial have no containers, so their edits never wait. The Forum plugin's topics live in forums, and a forum whose publishing rules set **Edits** to approval holds an author's changes for a moderator.
