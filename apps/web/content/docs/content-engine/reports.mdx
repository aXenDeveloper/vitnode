`reports` adds a **Report** button to your content. A reader picks a reason, and the report lands in the moderators' queue with a copy of what they saw. This page adds it to the newsroom's articles and follows one report to the ModCP.

## Before you begin

You need a content type with a [public API](/docs/content-engine/public-api) and a public record page, such as the article page from [Content page](/docs/content-engine/public-pages). Members do not have to write articles: staff-written articles can be reported too. To report, sign in with a member account; to read the report, use an account with moderator permissions, such as a root administrator.

<Steps>

<Step>

### Turn on reports

Edit `src/content/article.ts` and add `reports` after `publicApi`. This is an excerpt:

```ts title="plugins/newsroom/src/content/article.ts"
  publicApi: {
    path: "news",
    fields: ["id", "title", "slug", "body", "publishedAt"],
  },

  reports: true, // [!code ++]
```

Reports live in core tables, so there is nothing to migrate. The article type gets the moderator permissions `can_view_reports` and `can_manage_reports`, and a new public route, `GET /api/newsroom/content/news/permissions`, starts answering `canReport`.

</Step>

<Step>

### Ask whether the visitor may report

The button should only show where a report would be accepted, and that depends on who is looking. Create `src/pages/article-permissions.ts`. This is the complete file:

```ts title="plugins/newsroom/src/pages/article-permissions.ts"
import { useContentPermissions } from "@vitnode/core/tanstack/content";
import { fetcher } from "@vitnode/core/tanstack/fetcher";

import { manifest } from "@/manifest.gen";

/** What the visitor may do with each article on screen: `canEdit`, `canReport`. */
export const useArticlePermissions = (ids: readonly number[]) =>
  useContentPermissions({
    ids,
    queryKey: [manifest.id, "articles"],
    fetch: async request => {
      const res = await fetcher({
        plugin: manifest.id,
        method: "get",
        module: "content/news",
        path: "/permissions",
        args: { query: { ids: request.join(",") } },
      });
      if (res.status !== 200) throw new Error("Loading permissions failed.");

      return await res.json();
    },
  });
```

If you followed [Permissions](/docs/content-engine/public-permissions), this file already exists; reuse it. The same route answers both `canEdit` and `canReport`.

`canReport` is `true` for a public article the visitor did not write, guests included; the dialog asks a guest to sign in. An article staff wrote in the AdminCP has no author, so every reader may report it.

</Step>

<Step>

### Add the Report button

Edit `src/pages/article-page.tsx`. Add `contentTarget` to the existing `@vitnode/core/content` import, the other imports, and an `ArticleActions` component above `ArticlePage`. These are excerpts:

```tsx title="plugins/newsroom/src/pages/article-page.tsx"
import { contentTarget, zodRichTextDocument } from "@vitnode/core/content"; // [!code highlight]
import { ReportButton } from "@vitnode/core/tanstack/moderation";
import { useTranslations } from "use-intl";

import { articleContentType } from "@/content/article";

import { useArticlePermissions } from "./article-permissions";

/** Asked in the browser, so the cached page stays the same for everyone. */
const ArticleActions = ({ id, title }: { id: number; title: string }) => {
  const t = useTranslations("newsroom.articles");
  const { canReport } = useArticlePermissions([id]).of(id);

  return (
    <div className="flex flex-wrap gap-2">
      {canReport ? (
        <ReportButton
          preview={{ title }}
          target={contentTarget(manifest.id, articleContentType, id)}
          typeLabel={t("report_type")}
        />
      ) : null}
    </div>
  );
};
```

Then render it at the end of the article's `<header>`, below the date:

```tsx title="plugins/newsroom/src/pages/article-page.tsx"
      <header className="flex flex-col gap-2">
        {/* title and date as before */}
        <ArticleActions id={item.id} title={item.title} /> {/* [!code ++] */}
      </header>
```

- `contentTarget` names the record from the content type, so the type id always matches what the API registered.
- `preview` shows the article's title in the dialog, and `typeLabel` finishes its title, "What's wrong with this article?".
- The button loads its own messages, and its form only when the dialog opens.

If `ArticleActions` already exists from [Permissions](/docs/content-engine/public-permissions), add the `canReport` branch next to its **Edit** link, read both flags with `const { canEdit, canReport } = useArticlePermissions([id]).of(id)`, and pass `title={item.title}` where the header renders it.

</Step>

<Step>

### Add the label

Add `report_type` under `newsroom.articles` in `src/locales/en.json`:

```json title="plugins/newsroom/src/locales/en.json"
{
  "newsroom": {
    "articles": {
      "report_type": "article"
    }
  }
}
```

The dialog's own labels, such as the reasons, come from core.

</Step>

<Step>

### Grant the moderator permissions

A report needs a moderator with `can_view_reports` for articles to be seen, and `can_manage_reports` to be handled. A root administrator holds every moderator permission. For anyone else, open **AdminCP → Staff → Moderators**, add the user or role, and turn on the Newsroom report permissions, as [Configure moderators](/docs/dev/moderation/configure-moderators) shows.

</Step>

</Steps>

## Choose what moderators see

By default a report keeps the record's title and its public text, rich text, choice and file fields, frozen at the moment of the report. Pick the fields yourself when you want something else; they may even be private:

```ts title="plugins/newsroom/src/content/article.ts"
reports: { titleField: "title", snapshotFields: ["body"] },
```

## What the server checks

The button is only a hint. The report route checks again:

- The reader is signed in. A guest gets the sign-in prompt.
- The reader can read the record through the public API. A draft or a hidden record is `404`.
- One reader holds one open report per record, and files at most 20 reports an hour.

## Report from a list or a comment

- **Every row of a list.** Call the permissions hook once with every id on the page, and point each button at its row's title with `describedBy`, so a screen reader hears which record each **Report** belongs to. The example plugin's discussion list does this in `plugins/example/src/pages/discussions-page.tsx`.
- **Comments.** Add `reports: true` to the [comment type](/docs/content-engine/threads), read `canReport` from its own permissions hook, and pass `contentTarget(manifest.id, commentContentType, comment.id)`. `snapshotFields: ["body"]` gives moderators the comment's text, since a comment has no title.
