Replies let a comment answer another comment, so a conversation can branch. The thread route already returns each top-level comment followed by every answer below it; this page draws that as a tree, adds **Reply**, and keeps the shape when a comment in the middle is removed.

This continues the comment section from [Comments](/docs/content-engine/threads), where every comment is top level.

<Steps>

<Step>

### Raise the depth

Edit `src/content/comment.ts`. Put the depth in one exported constant, because the section uses it too:

```ts title="plugins/newsroom/src/content/comment.ts"
/** How deep replies nest. The reply form hides **Reply** at this depth. */
export const COMMENT_MAX_DEPTH = 4;

export const commentContentType = defineContentType({
  // ...the same fields and options as before
  thread: { parent: "parent", root: "article", maxDepth: COMMENT_MAX_DEPTH }, // [!code highlight]
});
```

A reply to a comment at depth 4 is refused, so nothing nests deeper than four levels. `maxDepth` changes no columns, so there is nothing to migrate.

</Step>

<Step>

### Build the tree

The thread route still answers with a flat list, depth first, so a parent always comes before its replies. Add a tree builder to the end of `src/pages/comment-data.ts`:

```ts title="plugins/newsroom/src/pages/comment-data.ts"
export interface CommentNode extends CommentItem {
  children: CommentNode[];
}

/** The flat, depth-first answer as a tree: a parent always comes before its replies. */
export const buildCommentTree = (
  items: readonly CommentItem[],
): CommentNode[] => {
  const nodes = new Map<number, CommentNode>();
  const roots: CommentNode[] = [];

  for (const item of items) {
    const node: CommentNode = { ...item, children: [] };
    nodes.set(item.id, node);
    const parent =
      item.parentId === null ? undefined : nodes.get(item.parentId);
    if (parent) parent.children.push(node);
    else roots.push(node);
  }

  return roots;
};
```

One pass is enough: every reply finds its parent in the map, because the parent came first.

</Step>

<Step>

### Render the tree

Edit `src/pages/comment-section.tsx`. First import the new pieces:

```tsx title="plugins/newsroom/src/pages/comment-section.tsx"
import type { ArticleComment, CommentNode } from "./comment-data";

import { COMMENT_MAX_DEPTH } from "@/content/comment";

import {
  buildCommentTree,
  commentsQueryKey,
  commentsQueryOptions,
} from "./comment-data";
```

Add a `CommentBranch` above `CommentSection`. It renders one comment and, indented below it, its replies:

```tsx title="plugins/newsroom/src/pages/comment-section.tsx"
const CommentBranch = ({
  actions,
  node,
}: {
  actions: CommentActions;
  node: CommentNode;
}) => {
  const t = useTranslations("newsroom.comments");

  return (
    <li className="flex flex-col gap-3">
      {node.record ? (
        <Comment actions={actions} comment={node.record} depth={node.depth} />
      ) : (
        // A tombstone: hidden, but it still has public replies below it.
        <p className="text-muted-foreground text-sm italic">{t("removed")}</p>
      )}
      {node.children.length > 0 ? (
        <ol className="flex flex-col gap-4 border-l-2 pl-3 md:pl-6">
          {node.children.map(child => (
            <CommentBranch actions={actions} key={child.id} node={child} />
          ))}
        </ol>
      ) : null}
    </li>
  );
};
```

**Removed comments.** `removed: true`, with `record: null`, is a comment readers may not see, such as a hidden one, that still has public replies. The branch shows a short placeholder and keeps the children, so the conversation keeps its shape. A hidden comment without public replies is not in the answer at all.

In `CommentSection`, build the tree from the loaded items:

```tsx title="plugins/newsroom/src/pages/comment-section.tsx"
  const items = useMemo(() => pages.flatMap(page => page.items), [pages]);
  const tree = useMemo(() => buildCommentTree(items), [items]);
```

and render it in place of the flat list, followed by a note when a page was cut short:

```tsx title="plugins/newsroom/src/pages/comment-section.tsx"
      {tree.length === 0 ? (
        <p className="text-muted-foreground leading-relaxed">{t("empty")}</p>
      ) : (
        <ol aria-busy={comments.isFetching} className="flex flex-col gap-6">
          {tree.map(node => (
            <CommentBranch actions={actions} key={node.id} node={node} />
          ))}
        </ol>
      )}

      {pages.some(page => page.truncated) ? (
        <p className="text-muted-foreground text-sm">{t("truncated")}</p>
      ) : null}
```

</Step>

### Add the Reply button

Each comment now needs more than its own data: whether the visitor may reply, the permissions of every comment and the save handler. Replace the `Comment` component, so it takes them as one `actions` object, and shows **Reply** with a composer that sends `parent`:

```tsx title="plugins/newsroom/src/pages/comment-section.tsx"
interface CommentActions {
  articleId: number;
  canReply: boolean;
  onSaved: CommentComposerProps["onDone"];
  permissionsOf: ReturnType<typeof useCommentPermissions>["of"];
}

const Comment = ({
  actions,
  comment,
  depth,
}: {
  actions: CommentActions;
  comment: ArticleComment;
  depth: number;
}) => {
  const t = useTranslations("newsroom.comments");
  const openEditor = useOpenEditor();
  const { canEdit } = actions.permissionsOf(comment.id);
  const [replying, setReplying] = useState(false);
  const [editing, setEditing] = useState<null | RichTextDocument>(null);
  const [isOpening, setIsOpening] = useState(false);

  return (
    <div className="flex flex-col gap-2">
      <p className="text-sm font-medium">
        {comment.author?.name ?? t("someone")}
      </p>

      {editing ? (
        <Composer
          body={editing}
          commentId={comment.id}
          label={t("form.edit_label")}
          mode="edit"
          onCancel={() => {
            setEditing(null);
          }}
          onDone={async outcome => {
            setEditing(null);
            await actions.onSaved(outcome);
          }}
        />
      ) : (
        <RichTextContent
          className="leading-relaxed text-pretty"
          content={comment.body}
        />
      )}

      {editing ? null : (
        <div className="flex flex-wrap items-center gap-1">
          {actions.canReply && depth < COMMENT_MAX_DEPTH ? (
            <Button
              aria-expanded={replying}
              onClick={() => {
                setReplying(!replying);
              }}
              size="sm"
              variant="ghost"
            >
              {t("reply")}
            </Button>
          ) : null}
          {canEdit ? (
            <Button
              isLoading={isOpening}
              onClick={async () => {
                setIsOpening(true);
                try {
                  setEditing(await openEditor(comment.id));
                } finally {
                  setIsOpening(false);
                }
              }}
              size="sm"
              variant="ghost"
            >
              {t("edit")}
            </Button>
          ) : null}
        </div>
      )}

      {replying ? (
        <Composer
          articleId={actions.articleId}
          label={t("form.answer_label", {
            name: comment.author?.name ?? t("someone"),
          })}
          mode="create"
          onCancel={() => {
            setReplying(false);
          }}
          onDone={async outcome => {
            setReplying(false);
            await actions.onSaved(outcome);
          }}
          parentId={comment.id}
        />
      ) : null}
    </div>
  );
};
```

Build `actions` in `CommentSection`, after `onSaved`:

```tsx title="plugins/newsroom/src/pages/comment-section.tsx"
  const actions: CommentActions = {
    articleId,
    canReply: Boolean(session.data?.user),
    onSaved,
    permissionsOf: permissions.of,
  };
```

- **Reply** shows for signed-in members while the comment sits above `COMMENT_MAX_DEPTH`. The server refuses deeper replies anyway.
- The reply composer posts `parent: comment.id`. `CommentComposer` already sends `parent`, so it needs no change.
- `onSaved` still invalidates the whole thread query, so a new reply appears in place under its parent.

```tsx title="plugins/newsroom/src/pages/comment-section.tsx"
import {
  useQueryClient,
  useSuspenseInfiniteQuery,
} from "@tanstack/react-query";
import { RichTextContent } from "@vitnode/core/components/rich-text";
import { Button, buttonVariants } from "@vitnode/core/components/ui/button";
import { Skeleton } from "@vitnode/core/components/ui/skeleton";
import {
  type RichTextDocument,
  zodRichTextDocument,
} from "@vitnode/core/content";
import { useSessionQuery } from "@vitnode/core/tanstack/auth";
import { fetcher } from "@vitnode/core/tanstack/fetcher";
import { HrefLink } from "@vitnode/core/tanstack/link";
import { lazy, Suspense, useMemo, useState } from "react";
import { toast } from "sonner";
import { useTranslations } from "use-intl";
import { z } from "zod";

import { COMMENT_MAX_DEPTH } from "@/content/comment";
import { manifest } from "@/manifest.gen";

import type { CommentComposerProps } from "./comment-composer";
import type { ArticleComment, CommentNode } from "./comment-data";

import {
  buildCommentTree,
  commentsQueryKey,
  commentsQueryOptions,
} from "./comment-data";
import { useCommentPermissions } from "./comment-permissions";

// The editor is heavy and most readers never write, so it loads on demand.
const CommentComposer = lazy(async () => await import("./comment-composer"));

const Composer = (props: CommentComposerProps) => (
  <Suspense fallback={<Skeleton className="h-40 w-full rounded-lg" />}>
    <CommentComposer {...props} />
  </Suspense>
);

const zodProposal = z
  .object({ body: zodRichTextDocument.optional() })
  .catch({});

/** Loads the latest text of a comment before editing it. */
const useOpenEditor = () => {
  const t = useTranslations("core.global.content_write");

  return async (commentId: number): Promise<null | RichTextDocument> => {
    const res = await fetcher({
      plugin: manifest.id,
      method: "get",
      module: "content/comments",
      path: "/{id}/edit",
      args: { params: { id: commentId } },
    });
    if (res.status !== 200) {
      const reason =
        res.status === 401
          ? "unauthenticated"
          : res.status === 403
            ? "forbidden"
            : res.status === 404
              ? "not_found"
              : "unknown";
      toast.error(t("title"), { description: t(reason) });

      return null;
    }

    const record = await res.json();
    const { approval } = record;
    // A pending edit opens on the proposal, not on the live text.
    const proposed =
      approval?.status === "pending" && approval.kind === "edit"
        ? zodProposal.parse(approval.values ?? {})
        : {};

    return proposed.body ?? record.values.body;
  };
};

interface CommentActions {
  articleId: number;
  canReply: boolean;
  onSaved: CommentComposerProps["onDone"];
  permissionsOf: ReturnType<typeof useCommentPermissions>["of"];
}

const Comment = ({
  actions,
  comment,
  depth,
}: {
  actions: CommentActions;
  comment: ArticleComment;
  depth: number;
}) => {
  const t = useTranslations("newsroom.comments");
  const openEditor = useOpenEditor();
  const { canEdit } = actions.permissionsOf(comment.id);
  const [replying, setReplying] = useState(false);
  const [editing, setEditing] = useState<null | RichTextDocument>(null);
  const [isOpening, setIsOpening] = useState(false);

  return (
    <div className="flex flex-col gap-2">
      <p className="text-sm font-medium">
        {comment.author?.name ?? t("someone")}
      </p>

      {editing ? (
        <Composer
          body={editing}
          commentId={comment.id}
          label={t("form.edit_label")}
          mode="edit"
          onCancel={() => {
            setEditing(null);
          }}
          onDone={async outcome => {
            setEditing(null);
            await actions.onSaved(outcome);
          }}
        />
      ) : (
        <RichTextContent
          className="leading-relaxed text-pretty"
          content={comment.body}
        />
      )}

      {editing ? null : (
        <div className="flex flex-wrap items-center gap-1">
          {actions.canReply && depth < COMMENT_MAX_DEPTH ? (
            <Button
              aria-expanded={replying}
              onClick={() => {
                setReplying(!replying);
              }}
              size="sm"
              variant="ghost"
            >
              {t("reply")}
            </Button>
          ) : null}
          {canEdit ? (
            <Button
              isLoading={isOpening}
              onClick={async () => {
                setIsOpening(true);
                try {
                  setEditing(await openEditor(comment.id));
                } finally {
                  setIsOpening(false);
                }
              }}
              size="sm"
              variant="ghost"
            >
              {t("edit")}
            </Button>
          ) : null}
        </div>
      )}

      {replying ? (
        <Composer
          articleId={actions.articleId}
          label={t("form.answer_label", {
            name: comment.author?.name ?? t("someone"),

          mode="create"
          onCancel={() => {
            setReplying(false);
          }}
          onDone={async outcome => {
            setReplying(false);
            await actions.onSaved(outcome);

          parentId={comment.id}
        />

const CommentBranch = ({
  actions,
  node,
}: {
  actions: CommentActions;
  node: CommentNode;
}) => {
  const t = useTranslations("newsroom.comments");

  return (
    <li className="flex flex-col gap-3">
      {node.record ? (
        <Comment actions={actions} comment={node.record} depth={node.depth} />
      ) : (
        // A tombstone: hidden, but it still has public replies below it.
        <p className="text-muted-foreground text-sm italic">{t("removed")}</p>
      )}
      {node.children.length > 0 ? (
        <ol className="flex flex-col gap-4 border-l-2 pl-3 md:pl-6">
          {node.children.map(child => (
            <CommentBranch actions={actions} key={child.id} node={child} />

        </ol>
      ) : null}
    </li>
  );

export const CommentSection = ({
  articleId,
  articleSlug,
}: {
  articleId: number;
  articleSlug: string;
}) => {
  const t = useTranslations("newsroom.comments");
  const queryClient = useQueryClient();
  const session = useSessionQuery();
  const [composerKey, setComposerKey] = useState(0);
  const comments = useSuspenseInfiniteQuery(commentsQueryOptions(articleId));

  const { pages } = comments.data;
  const items = useMemo(() => pages.flatMap(page => page.items), [pages]);
  const tree = useMemo(() => buildCommentTree(items), [items]);
  const permissions = useCommentPermissions(
    items.flatMap(item => (item.record ? [item.id] : [])),
  );

  const onSaved: CommentComposerProps["onDone"] = async ({
    edited,
    pending,
  }) => {
    if (pending) {
      toast.info(t("pending.title"), { description: t("pending.desc") });
    } else {
      const key = edited ? "edited" : "created";
      toast.success(t(`${key}.title`), { description: t(`${key}.desc`) });
    }
    // Refetches every loaded page in order, with the new count.
    await queryClient.invalidateQueries({
      queryKey: commentsQueryKey(articleId),
    });
  };

  const actions: CommentActions = {
    articleId,
    canReply: Boolean(session.data?.user),
    onSaved,
    permissionsOf: permissions.of,
  };

  return (
    <section aria-labelledby="comments-title" className="flex flex-col gap-6">
      <h2 className="text-xl font-semibold text-balance" id="comments-title">
        {t("title", { count: pages[0]?.replyCount ?? 0 })}
      </h2>

      {tree.length === 0 ? (
        <p className="text-muted-foreground leading-relaxed">{t("empty")}</p>
      ) : (
        <ol aria-busy={comments.isFetching} className="flex flex-col gap-6">
          {tree.map(node => (
            <CommentBranch actions={actions} key={node.id} node={node} />
          ))}
        </ol>
      )}

      {pages.some(page => page.truncated) ? (
        <p className="text-muted-foreground text-sm">{t("truncated")}</p>
      ) : null}

      {comments.hasNextPage ? (
        <Button
          className="self-start"
          disabled={comments.isFetching}
          isLoading={comments.isFetchingNextPage}
          onClick={async () => {
            const next = await comments.fetchNextPage();
            if (next.isError) {
              toast.error(t("load_failed.title"), {
                description: t("load_failed.desc"),
              });
            }
          }}
          variant="outline"
        >
          {t("load_more")}
        </Button>
      ) : null}

      {session.data?.user ? (
        <Composer
          articleId={articleId}
          // A new key gives the next comment a fresh, empty editor.
          key={composerKey}
          label={t("form.label")}
          mode="create"
          onDone={async outcome => {
            setComposerKey(composerKey + 1);
            await onSaved(outcome);
          }}
          parentId={null}
        />
      ) : (
        <HrefLink
          className={buttonVariants({
            className: "self-start",
            variant: "outline",
          })}
          href={`/login?returnTo=${encodeURIComponent(`/news/${articleSlug}`)}`}
        >
          {t("sign_in")}
        </HrefLink>
      )}
    </section>
  );
};
```

## Pages and long conversations

- **Pages are top-level comments.** `first` counts top-level comments, and each comes with every reply below it. **Load more comments** adds the next ones; replies never split across pages.
- **Truncated pages.** One page holds at most 500 comments in total. When deep replies do not fit, `truncated` is `true` and the section says so instead of pretending the conversation ends there.
- **New top-level comments** land at the end, because comments are oldest first. While pages remain, **Load more comments** reaches them.
- **Permissions** are still one hook call for every loaded comment. It splits more than 50 ids into batches, so a long thread keeps its **Edit** buttons.

The server keeps the tree valid on every write, in the AdminCP too: the parent must exist, be public and belong to the same article; a comment never answers itself or one of its own answers; and nothing nests deeper than `maxDepth`. The Forum plugin's `plugins/forum/src/pages/thread.tsx` builds the same thread with collapsible branches and permalinks.
