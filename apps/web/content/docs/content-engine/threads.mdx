The `thread` option turns a content type into replies that answer each other under one record, like comments under a forum topic. The server keeps the tree valid and returns it a page at a time; your page draws it. This guide follows the Forum plugin's comments: the content type first, then the comment section in `plugins/forum/src/pages/`.

You need the root content type, here `forum.topic`, with a [public API](/docs/content-engine/public-api) and a page. For members to reply, read [Public write](/docs/content-engine/public-write) too.

<Steps>

<Step>

### Define the reply

```ts title="plugins/forum/src/content/comment.ts"
import { defineContentType, field } from "@vitnode/core/content";

import { topicContentType } from "@/content/topic";

export const commentContentType = defineContentType({
  id: "forum.comment",
  tableName: "forum_comments",

  fields: {
    slug: field.slug({ generated: true }),
    body: field.richText({ required: true }),
    author: field.user(),
    topic: field.relation({
      target: () => topicContentType,
      required: true,
      container: true,
      onDelete: "cascade",
    }),
    parent: field.relation({ self: true, nullable: true, onDelete: "set null" }),
  },

  publication: true,
  visibility: true,
  reports: { snapshotFields: ["body"] },

  publicApi: {
    path: "comments",
    fields: ["id", "slug", "body", "topic", "parent", "publishedAt", "createdAt"],
    people: ["author"],
  },

  publicWrite: {
    ownership: { field: "author" },
    create: { fields: ["body", "topic", "parent"], status: "published" },
    update: { fields: ["body"] },
  },

  thread: { parent: "parent", root: "topic", maxDepth: 6 },
});
```

- `parent` is the reply being answered, or `null` for a direct answer to the topic.
- `topic` is the **root**. `container: true` puts the comment in the topic's forum, so the forum's [publishing policies](/docs/content-engine/container-policies) and moderators apply to comments too.
- `slug` with `generated: true` gets a random token such as `k3v9q2m7xa`, because a comment has no title.
- A comment's place is fixed when it is written. `parent` and `topic` cannot be edited.

</Step>

### Read the thread

`GET /comments/thread?root={topicId}` returns a page of top-level replies, oldest first, each followed by every public answer below it:

```ts title="plugins/forum/src/pages/thread-data.ts"
const res = await fetcher({
  plugin: manifest.id,
  method: "get",
  module: "content/comments",
  path: "/thread",
  args: { query: { root: String(topicId), first: 20, ...(after ? { after } : {}) } },
});
```

The answer is flat, so a parent always comes before its replies:

```json
{
  "items": [
    { "depth": 1, "id": 17, "parentId": null, "removed": false, "record": { "id": 17, "body": {}, "author": {} } },
    { "depth": 2, "id": 18, "parentId": 17, "removed": true, "record": null },
    { "depth": 3, "id": 21, "parentId": 18, "removed": false, "record": { "id": 21 } }
  ],
  "pageInfo": { "endCursor": "WyIyMDI2...", "hasNextPage": false, "totalCount": 1 },
  "replyCount": 2,
  "truncated": false
}
```

Warm the first page in the topic page's loader, so comments are in the server-rendered HTML.

</Step>

<Step>

### Draw the tree

Turn the flat list into a tree in one pass, then render nested `<ol>` lists:

```tsx title="plugins/forum/src/pages/thread.tsx"
const buildThreadTree = (items: ThreadNode[]) => {
  const nodes = new Map<number, ThreadTreeNode>();
  const roots: ThreadTreeNode[] = [];
  for (const item of items) {
    const node = { ...item, children: [] };
    nodes.set(item.id, node);
    const parent = item.parentId === null ? undefined : nodes.get(item.parentId);
    if (parent) parent.children.push(node);
    else roots.push(node);
  }

  return roots;
};

const ThreadNodeView = ({ node }: { node: ThreadTreeNode }) => (
  <li>
    {node.record ? (
      <CommentBody comment={node.record} />
    ) : (
      <p className="text-muted-foreground italic">{t("removed")}</p>
    )}
    {node.children.length > 0 ? (
      <ol className="border-l-2 pl-3 md:pl-6">
        {node.children.map(child => <ThreadNodeView key={child.id} node={child} />)}
      </ol>
    ) : null}
  </li>
);
```

**Tombstones.** `removed: true` is a reply readers can't see, such as a hidden one, that still has public answers. Show a short placeholder and keep its children, so the conversation keeps its shape. A hidden reply with no answers is left out.

</Step>

<Step>

### Load more pages

Keep the pages you loaded and pass the last `endCursor` as `after`:

```tsx title="plugins/forum/src/pages/thread.tsx"
{last.pageInfo.hasNextPage ? (
  <Button onClick={loadMore} variant="outline">{t("load_more")}</Button>
) : null}
{last.truncated ? <p>{t("truncated")}</p> : null}
```

One answer holds at most 500 replies. `truncated: true` means some deep answers did not fit; say so instead of pretending the thread ends there. `replyCount` counts every public reply, the number for a "5 comments" heading.

</Step>

<Step>

### Reply, edit and report

Ask what the visitor may do with every reply on screen, in one request:

```tsx title="plugins/forum/src/pages/thread.tsx"
const permissions = useCommentPermissions(
  items.flatMap(item => (item.record ? [item.id] : [])),
);

const { canEdit, canReport } = permissions.of(comment.id);
```

`useCommentPermissions` wraps `useContentPermissions` with the `content/comments` route, like [`useDiscussionPermissions`](/docs/content-engine/reports#ask-who-may-report-what). Then:

- **Reply** posts `{ values: { body, parent: comment.id, topic: topicId } }` with `useContentPublicWrite`, like the [create form](/docs/content-engine/public-write-frontend). Show it to signed-in members while the reply sits above `maxDepth`.
- **Edit** appears when `canEdit`. It loads `GET /comments/{id}/edit` and saves with `PATCH`, like the [edit form](/docs/content-engine/public-write-edit).
- **Report** appears when `canReport`, with `contentTarget(manifest.id, commentContentType, comment.id)`. See [Report content](/docs/content-engine/reports).

When the forum's policy holds new comments for a moderator, the post answers `approval.status: "pending"`. Tell the author it is waiting; the comment appears in the thread after approval.

</Step>

</Steps>

## What the server checks

Every reply is placed on the server, in the AdminCP too. A broken rule answers `400` with an issue on the field:

| Rule                                                 | Message                                                         |
| ---------------------------------------------------- | --------------------------------------------------------------- |
| The parent exists and is public                      | `The reply you are answering does not exist.`                   |
| The parent is under the same topic                   | `The reply you are answering belongs to another conversation.`  |
| A reply never answers itself or one of its answers   | `A reply cannot answer itself or one of its answers.`           |
| Nothing sits deeper than `maxDepth`                  | `Replies nest at most 6 levels deep. Answer a reply higher up.` |

A missing, draft or hidden topic makes `GET /thread` answer `404`. Every option is in the [`thread` reference](/docs/content-engine/reference#thread).

## Use it in another plugin

The forum's `thread-data.ts`, `thread.tsx` and `comment-composer.tsx` are a reference to copy, not an export. Change the module to `content/` plus your reply type's path, `topic` to your `thread.root` field, and the depth limit to your `maxDepth`. The tree, tombstones, paging and buttons need nothing else.

## Check the result

Open a topic with replies, such as `/forum/topics/show-us-your-first-content-engine-type`. Replies nest under the one they answer, a hidden reply leaves **This comment was removed.** with its answer still below it, your own replies show **Edit**, and the others show **Report**.
