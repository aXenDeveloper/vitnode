Comments are records of their own, in a comment content type that points at the article it answers. The `thread` option gives that type a route that returns an article's comments a page at a time, and the server checks where every comment may go. This page adds a comment list and a composer under each article.

## Before you begin

You need:

- **The article type with its public API and public page**, from the beginner path up to [Content page](/docs/content-engine/public-pages). The article itself needs no `author` and no `publicWrite`. Staff can keep writing every article in the AdminCP. The comment type below has its own `author` field and its own `publicWrite`, which is what lets members comment.
- **Member accounts.** Signing in is part of every VitNode app; it does not depend on members writing articles.
- **`@tanstack/react-query` in the plugin.** Skip this if [Embedded list](/docs/content-engine/public-lists-embed#add-tanstack-query-to-the-plugin) or [Create form](/docs/content-engine/public-write-frontend#add-tanstack-query-to-the-plugin) already added it; otherwise run this from the workspace root:

### Define the comment type

Create `src/content/comment.ts`. This is the complete file:

```ts title="plugins/newsroom/src/content/comment.ts"
import { defineContentType, field } from "@vitnode/core/content";

import { articleContentType } from "@/content/article";

export const commentContentType = defineContentType({
  id: "newsroom.comment",
  tableName: "newsroom_comments",

  fields: {
    slug: field.slug({ generated: true }),
    body: field.richText({ required: true }),
    author: field.user(),
    article: field.relation({
      target: () => articleContentType,
      required: true,
      onDelete: "cascade",
    }),
    parent: field.relation({
      self: true,
      nullable: true,
      onDelete: "set null",
    }),
  },

  publication: true,
  visibility: true,

  publicApi: {
    path: "comments",
    fields: ["id", "slug", "body", "article", "parent", "publishedAt"],
    people: ["author"],
  },

  publicWrite: {
    ownership: { field: "author" },
    create: { fields: ["body", "article", "parent"], status: "published" },
    update: { fields: ["body"] },
  },

  thread: { parent: "parent", root: "article", maxDepth: 1 },

  admin: { path: "newsroom/comments", titleField: "slug" },
});
```

- **`article`** is the comment's **root**, the record it belongs to. It must be a required relation to another content type. `onDelete: "cascade"` removes the comments with their article.
- **`parent`** is the comment being answered, or `null`. `thread` requires it even for flat comments; `maxDepth: 1` keeps every comment top level until [Replies](/docs/content-engine/threads-frontend).
- **`slug`** with `generated: true` gets a random token, because a comment has no title. The public API needs exactly one slug.
- **`publicWrite`** lets members post `body` under an `article`, and `create.status: "published"` makes a new comment public at once. `update` lets authors fix their text later, in [Comment editing](/docs/content-engine/threads-editing). A comment's place is fixed when it is written, so `parent` and `article` are never in `update.fields`.
- **`visibility`** lets moderators hide a comment, and **`admin`** gives staff a list of comments in the AdminCP.

### Read the comments

Create `src/pages/comment-data.ts`. This is the complete file. All loaded pages of one article's comments live in one infinite query, so refreshing it reloads every page in order:

```ts title="plugins/newsroom/src/pages/comment-data.ts"
import { infiniteQueryOptions } from "@tanstack/react-query";
import {
  zodContentPublicPerson,
  zodRichTextDocument,
} from "@vitnode/core/content";
import { fetcher } from "@vitnode/core/tanstack/fetcher";
import { z } from "zod";

import { manifest } from "@/manifest.gen";

/** Top-level comments per page. The thread route accepts 1 to 50. */
const COMMENTS_PAGE_SIZE = 20;

/** One comment as `publicApi.fields` and `people` return it. */
const zodComment = z.object({
  author: zodContentPublicPerson.nullable().catch(null),
  body: zodRichTextDocument,
  id: z.number(),
  publishedAt: z.string().nullable(),
});

const zodCommentPage = z.object({
  items: z.array(
    z.object({
      depth: z.number(),
      id: z.number(),
      parentId: z.number().nullable(),
      record: zodComment.nullable(),
      removed: z.boolean(),
    }),
  ),
  pageInfo: z.object({
    endCursor: z.string().nullable(),
    hasNextPage: z.boolean(),
    totalCount: z.number(),
  }),
  replyCount: z.number(),
  truncated: z.boolean(),
});

export type CommentPage = z.infer<typeof zodCommentPage>;

export type CommentItem = CommentPage["items"][number];

export type ArticleComment = NonNullable<CommentItem["record"]>;

const fetchCommentPage = async (articleId: number, after?: string) => {
  const res = await fetcher({
    plugin: manifest.id,
    method: "get",
    module: "content/comments",
    path: "/thread",
    args: {
      query: {
        root: String(articleId),
        first: COMMENTS_PAGE_SIZE,
        ...(after ? { after } : {}),
      },
    },
  });
  if (res.status !== 200) throw new Error("Loading the comments failed.");

  // The thread route types `record` loosely, so parse it once here.
  return zodCommentPage.parse(await res.json());
};

export const commentsQueryKey = (articleId: number) =>
  [manifest.id, "comments", articleId] as const;

/** Every loaded page under one key, so a refetch reloads them all in order. */
export const commentsQueryOptions = (articleId: number) =>
  infiniteQueryOptions({
    getNextPageParam: (last: CommentPage) =>
      last.pageInfo.hasNextPage
        ? (last.pageInfo.endCursor ?? undefined)
        : undefined,
    initialPageParam: undefined as string | undefined,
    queryFn: async ({ pageParam }) =>
      await fetchCommentPage(articleId, pageParam),
    queryKey: commentsQueryKey(articleId),
  });
```

- `GET /comments/thread?root={articleId}` returns up to `first` top-level comments, oldest first. `endCursor` asks for the next page.
- `items` is a flat list, and each comment in it has `depth`, `parentId` and `record`. With `maxDepth: 1`, every item is top level.
- The thread route types `record` loosely, so `zodCommentPage` checks the fields `publicApi` returns once, here. `author` comes from `people` as a small public profile, or `null` for a deleted account.
- `replyCount` counts every public comment, for the "2 comments" heading.

### Write the composer

Create `src/pages/comment-composer.tsx`. This is the complete file. It posts one comment and reports where it ended up:

```tsx title="plugins/newsroom/src/pages/comment-composer.tsx"
import {
  AutoForm,
  type AutoFormOnSubmit,
  AutoFormSubmitButton,
} from "@vitnode/core/components/form/auto-form";
import { AutoFormEditor } from "@vitnode/core/components/form/fields/editor";
import {
  emptyRichTextDocument,
  isRichTextEmpty,
  zodRichTextDocument,
} from "@vitnode/core/content";
import { useContentPublicWrite } from "@vitnode/core/tanstack/content";
import { fetcher } from "@vitnode/core/tanstack/fetcher";
import { useTranslations } from "use-intl";
import { z } from "zod";

import { manifest } from "@/manifest.gen";

/** Where a new comment ended up. Only `published` is in the public thread. */
export type CommentOutcome = "draft" | "pending" | "published";

export interface CommentComposerProps {
  articleId: number;
  label: string;
  /** Called after the server stored the comment. */
  onPosted: (outcome: CommentOutcome) => Promise<void>;
  /** The comment being answered, or `null` for the article itself. */
  parentId: null | number;
}

const createSchema = (required: string) =>
  z.object({
    body: zodRichTextDocument
      .refine(doc => !isRichTextEmpty(doc), required)
      .default(emptyRichTextDocument()),
  });

const CommentComposer = ({
  articleId,
  label,
  onPosted,
  parentId,
}: CommentComposerProps) => {
  const t = useTranslations("newsroom.comments.form");
  const write = useContentPublicWrite({ fields: ["body"] });

  const onSubmit: AutoFormOnSubmit<ReturnType<typeof createSchema>> = async (
    { body },
    form,
  ) => {
    const record = await write.submit(
      form,
      async () =>
        await fetcher({
          plugin: manifest.id,
          method: "post",
          module: "content/comments",
          path: "/",
          args: {
            body: { values: { article: articleId, body, parent: parentId } },
          },
        }),
    );
    if (!record) return;

    // A pending comment is a draft too, so ask about approval first.
    await onPosted(
      record.approval?.status === "pending"
        ? "pending"
        : record.status === "published"
          ? "published"
          : "draft",
    );
  };

  return (
    <AutoForm
      aria-label={label}
      className="flex flex-col gap-3"
      fields={[
        {
          id: "body",
          component: fieldProps => (
            <AutoFormEditor {...fieldProps} format="json" label={label} />
          ),
        },
      ]}
      formSchema={createSchema(t("required"))}
      layout={fields => <>{fields.body}</>}
      onSubmit={onSubmit}
    >
      <AutoFormSubmitButton className="self-start">
        {t("submit")}
      </AutoFormSubmitButton>
    </AutoForm>
  );
};

export default CommentComposer;
```

- **The request** posts `{ values: { article, body, parent } }`; `parent: null` answers the article itself. The server fills `author` from the session.
- **`write.submit`** returns the stored comment, or `null` after showing why the server said no, such as an expired session.
- **The outcome** reads both `approval` and `status`. A comment waiting for a moderator is also a draft, so `approval` is checked first.
- The file has a default export because the section loads it with `lazy`. The editor is heavy, and most readers never write.

</Step>

### Render the section

Create `src/pages/comment-section.tsx`. This is the complete file:

```tsx title="plugins/newsroom/src/pages/comment-section.tsx"
import { useInfiniteQuery, useQueryClient } from "@tanstack/react-query";
import { RichTextContent } from "@vitnode/core/components/rich-text";
import { Button, buttonVariants } from "@vitnode/core/components/ui/button";
import { Skeleton } from "@vitnode/core/components/ui/skeleton";
import { useSessionQuery } from "@vitnode/core/tanstack/auth";
import { HrefLink } from "@vitnode/core/tanstack/link";
import { lazy, Suspense, useMemo, useState } from "react";
import { toast } from "sonner";
import { useTranslations } from "use-intl";

import type { CommentComposerProps, CommentOutcome } from "./comment-composer";
import type { ArticleComment } from "./comment-data";

import { commentsQueryKey, commentsQueryOptions } from "./comment-data";

// The editor is heavy and most readers never write, so it loads on demand.
const CommentComposer = lazy(async () => await import("./comment-composer"));

const Composer = (props: CommentComposerProps) => (
  <Suspense fallback={<Skeleton className="h-40 w-full rounded-lg" />}>
    <CommentComposer {...props} />
  </Suspense>
);

/** Who wrote a comment, and what they said. */
const CommentBody = ({ comment }: { comment: ArticleComment }) => {
  const t = useTranslations("newsroom.comments");

  return (
    <div className="flex flex-col gap-2">
      <p className="text-sm font-medium">
        {comment.author?.name ?? t("someone")}
      </p>
      <RichTextContent
        className="leading-relaxed text-pretty"
        content={comment.body}
      />
    </div>
  );
};

export const CommentSection = ({
  articleId,
  articleSlug,
}: {
  articleId: number;
  articleSlug: string;
}) => {
  const t = useTranslations("newsroom.comments");
  const queryClient = useQueryClient();
  const session = useSessionQuery();
  const [composerKey, setComposerKey] = useState(0);
  const comments = useInfiniteQuery(commentsQueryOptions(articleId));

  const pages = comments.data?.pages;
  const items = useMemo(
    () => pages?.flatMap(page => page.items) ?? [],
    [pages],
  );

  const onPosted = async (outcome: CommentOutcome) => {
    if (outcome !== "published") {
      // Not in the public thread, so there is nothing to refresh.
      toast.info(t(`${outcome}.title`), { description: t(`${outcome}.desc`) });

      return;
    }

    toast.success(t("created.title"), { description: t("created.desc") });
    // Refetches every loaded page in order, with the new count.
    await queryClient.invalidateQueries({
      queryKey: commentsQueryKey(articleId),
    });
  };

  return (
    <section aria-labelledby="comments-title" className="flex flex-col gap-6">
      <h2 className="text-xl font-semibold text-balance" id="comments-title">
        {t("title", { count: pages?.[0]?.replyCount ?? 0 })}
      </h2>

      {comments.isPending ? (
        <div aria-busy="true" className="flex flex-col gap-4">
          <span className="sr-only" role="status">
            {t("loading")}
          </span>
          {[0, 1].map(key => (
            <div className="flex flex-col gap-2" key={key}>
              <Skeleton className="h-4 w-32" />
              <Skeleton className="h-4 w-full" />
            </div>
          ))}
        </div>
      ) : comments.isError && items.length === 0 ? (
        <div className="flex flex-col items-start gap-3">
          <p className="text-muted-foreground leading-relaxed" role="alert">
            {t("load_failed.desc")}
          </p>
          <Button
            isLoading={comments.isFetching}
            onClick={async () => {
              await comments.refetch();
            }}
            variant="outline"
          >
            {t("retry")}
          </Button>
        </div>
      ) : items.length === 0 ? (
        <p className="text-muted-foreground leading-relaxed">{t("empty")}</p>
      ) : (
        <ol aria-busy={comments.isFetching} className="flex flex-col gap-6">
          {items.map(item =>
            item.record ? (
              <li key={item.id}>
                <CommentBody comment={item.record} />
              </li>
            ) : null,
          )}
        </ol>
      )}

      {comments.hasNextPage ? (
        <Button
          className="self-start"
          disabled={comments.isFetching}
          isLoading={comments.isFetchingNextPage}
          onClick={async () => {
            const next = await comments.fetchNextPage();
            if (next.isError) {
              toast.error(t("load_failed.title"), {
                description: t("load_failed.desc"),
              });
            }
          }}
          variant="outline"
        >
          {t("load_more")}
        </Button>
      ) : null}

      {session.data?.user ? (
        <Composer
          articleId={articleId}
          // A fresh key gives the next comment an empty editor.
          key={composerKey}
          label={t("form.label")}
          onPosted={async outcome => {
            setComposerKey(key => key + 1);
            await onPosted(outcome);
          }}
          parentId={null}
        />
      ) : (
        <HrefLink
          className={buttonVariants({
            className: "self-start",
            variant: "outline",
          })}
          href={`/login?returnTo=${encodeURIComponent(`/news/${articleSlug}`)}`}
        >
          {t("sign_in")}
        </HrefLink>
      )}
    </section>
  );
};
```

- **`useInfiniteQuery`** reads the pages the article's loader warms in the next step, so the comments are in the server-rendered HTML. When that warm-up failed, it loads them in the browser.
- **One state at a time.** `isPending` shows a skeleton with one screen reader label, an error with no comments shows **Try again**, an empty thread says so, and anything else is the list. A failed refetch keeps the comments already on screen.
- **`onPosted`** refreshes the thread only for a published comment. TanStack Query refetches every loaded page from the first, so the new comment and the heading's count update together. Drafts and pending comments only get their message; see [What a new comment can become](#what-a-new-comment-can-become).
- **Load more comments** calls `fetchNextPage` with the last cursor. It is disabled during any fetch, so a double click never loads a page twice.
- **Guests** see a sign-in link that brings them back to the article.

</Step>

import type { PluginRoutePageProps } from "@vitnode/core/routing";
import { defineRoute } from "@vitnode/core/tanstack/plugin-routes";

import { commentsQueryOptions } from "./comment-data"; // [!code ++]
import { CommentSection } from "./comment-section"; // [!code ++]

export const route = defineRoute({
  load: async ({ context, params }) => {
    const page = await loadArticle(params.slug);
    // [!code ++:5]
    // The first page of comments arrives with the article's HTML. A failure
    // leaves the section to show its own error instead of breaking the page.
    await context.queryClient
      .infiniteQuery(commentsQueryOptions(page.item.id))
      .catch(() => null);

    return page;

  head: ({ loaderData }) =>
    contentDeliveryPageHead(loaderData?.metadata, {
      title: loaderData?.item.title,
    }),
});

## What a new comment can become

`POST /comments` answers `201` with the stored comment. Its `status` and `approval` say whether readers can see it:

| `status` | `approval` | When | What the section does |
| --- | --- | --- | --- |
| `"published"` | `null` | `create.status: "published"`, as here | **Comment posted**, and the thread refreshes |
| `"draft"` | `null` | `create.status: "draft"` | **Comment saved as a draft**; staff publish it in the AdminCP |
| `"draft"` | `{ status: "pending" }` | The article is filed in a container that holds new comments for approval | **Your comment is waiting for a moderator** |

A newsroom comment can never be pending, because articles are not filed in a container. Pending comments need two more settings: mark the root relation `container: true`, and give its target a `field.container()` whose definition has `policies`. The Forum plugin's comments are set up this way:

```ts title="plugins/forum/src/content/comment.ts (excerpt)"
topic: field.relation({
  target: () => topicContentType,
  required: true,
  container: true, // the comment follows its topic's forum and its rules
  onDelete: "cascade",
}),
```

A moderator then sets **New posts** to **Wait for approval** for comments in a forum's [publishing rules](/docs/content-engine/container-policies). [Approvals](/docs/content-engine/approvals#drafts-and-approval) explains the difference between a draft and a pending submission.

## Deleting a comment that has replies

`POST /{publicApi.path}/{id}/delete` removes a comment for good when nothing answers it. When it has replies, the row stays as a placeholder instead, marked with `deletedAt` and `deletedBy`, so its answers keep their place in the tree. A placeholder is never public: lists, the detail route and search skip it, and the thread returns it with `record: null` and

```json
"deleted": { "byAuthor": true, "createdAt": "2026-10-25T18:02:11.000Z" }
```

without its text or its author, the way Reddit shows **[deleted]**. `byAuthor` is `false` when a moderator deleted it. Deleting the last reply under a placeholder removes the placeholder too.

A hidden reply with answers looks exactly the same to readers who can't see it: same `deleted` object, with `byAuthor` telling whether its author hid it or a moderator did. Moderators and the author still get the real comment, flagged `hidden: true`.

## What the server checks

- **Signed out.** `POST /comments` answers `401`; the section never offers the composer to guests.
- **Placement.** The article must be public (or hidden, for a reader allowed to see it), the parent must belong to the same article, and nothing may nest deeper than `maxDepth`. A broken rule answers `400` with an issue on `parent`, which the composer shows as a toast.
- **Hidden articles.** A comment is only as public as its article. Once the article is unpublished, its comments drop out of the thread and their own routes answer `404`. A *hidden* article keeps its conversation going for the people who can still see it - its authors, editors and moderators: they read the thread and comment as usual, and that response is never cached for anyone else. Everybody else gets `404`.
- **Search and Discover.** Comments are indexed as "commented on <article>" by default, as long as the article type is searchable and the comment has a `delivery.path`. See [Comments get this for free](/docs/content-engine/search#comments-get-this-for-free).
