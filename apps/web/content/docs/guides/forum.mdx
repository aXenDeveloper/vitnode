`@vitnode/forum` adds a community forum to a VitNode app: a tree of forums,
topics inside them and threaded comments. It is built only from
Content Engine pieces - a [container](/docs/content-engine/containers) for the
forums, two content types and a [thread](/docs/content-engine/threads) - so
everything you learn here works the same way in your own plugins.

<Callout type="info" title="Lives in the monorepo">
  The plugin is `private: true` and ships with the VitNode repository, like the
  `newsroom` plugin. It is not published to npm yet.
</Callout>

<Steps>
  <Step>

### Enable the API plugin

Add the API factory to `vitnode.api.config.ts` - in `apps/web` for a single
app, and in `apps/api` too for a split deployment.

```ts title="apps/web/src/vitnode.api.config.ts"
import { forumApiPlugin } from '@vitnode/forum/config.api' // [!code ++]

export const vitNodeApiConfig = buildApiConfig({
  plugins: [
    forumApiPlugin(), // [!code ++]
  ],
})
```

  </Step>
  <Step>

### Enable the web plugin

The web factory brings the pages, the AdminCP **Forums** screen and the
translations.

```ts title="apps/web/src/vitnode.config.ts"
import { forumPlugin } from '@vitnode/forum/config' // [!code ++]

export const vitNodeConfig = buildConfig({
  plugins: [
    forumPlugin(), // [!code ++]
  ],
})
```

  </Step>
  <Step>

### Migrate and start

The plugin owns two tables, `forum_topics` and `forum_comments`. Run the
migrations, then start the app.

<Tabs groupId="package-manager" persist items={["bun", "pnpm", "npm"]} label="Migrate and start the forum">

```bash tab="bun"
bun run db:migrate
bun dev
```

```bash tab="pnpm"
pnpm db:migrate
pnpm dev
```

```bash tab="npm"
npm run db:migrate
npm run dev
```

</Tabs>

  </Step>
  <Step>

### Create your forums

In AdminCP, open **Forums** and create a few. Forums nest up to four levels
deep, and you can drag them to reorder. A forum's **Icon** accepts the same
`icon:name` or emoji value as role prefixes.

## Pages members get

| Page                     | What it does                                                        |
| ------------------------ | ------------------------------------------------------------------- |
| `/forum`                 | A feed of topics from every forum you can read, with the forum list |
| `/forum/:slug`           | Subforums and the topics of one forum, in the same sortable feed    |
| `/forum/create/topic`    | Start a topic (signed-in members)                                   |
| `/forum/topics/:slug`    | The topic, its comments, and a comment box                          |
| `/forum/topics/:id/edit` | Edit your own topic                                                 |
| `/forum/comments/:slug`  | Permalink of one comment - redirects to its place in the topic      |
| `/forum/me/pending`      | Your posts a moderator approved, declined, or has not looked at yet |

## Sort the feed

`/forum` works like a Reddit front page: one feed of topics from every forum
the visitor may read. Beside it sits a sidebar that follows you down the page:
the forum's description, how many topics and comments it holds, a **New topic**
button and the forum tree (on phones, a row of forum chips instead). Each forum
page shows its own topics the same way.

Every topic is a card: the forum's icon, then its forum, author and age, the
title and a short excerpt. The card's footer holds its points and reactions -
members react right from the feed - and a link straight to its comments.

| Sort   | URL                | Shows first                                                  |
| ------ | ------------------ | ------------------------------------------------------------ |
| Hot    | `/forum`           | Busy topics that are still fresh - the default               |
| New    | `?sort=new`        | The newest topics                                            |
| Active | `?sort=active`     | Topics with the latest comment, like a classic forum         |
| Top    | `?sort=top&t=week` | The most points today, this week, month or year, or all time |

Pages go `?page=2` and on, up to page 40. The ranking is shared by everyone and
cached for a minute; a new topic or comment refreshes it at once, a new
reaction - or a new value for a reaction in AdminCP - within a minute. Topics
in forums the visitor cannot read never make it into their feed.

Need the feed in your own component? Call the same route:

```ts
import { fetcher } from '@vitnode/core/tanstack/fetcher'

const res = await fetcher({
  plugin: '@vitnode/forum',
  method: 'get',
  module: 'forum',
  path: '/feed',
  args: { query: { page: 1, sort: 'top', t: 'month' } },
})
```

Add `forumId` to the query for one forum's topics only.

## Points come from reactions

There is no up/down voting. A topic's or comment's **points** are its
reactions, each worth what you set in **AdminCP → Reactions**. Say `like` is
worth 1, `thanks` 2, `sad` 0 and `disagree` -1: a topic with three likes and
one thanks has 5 points. In other words, points are exactly what the
reaction pills under a post add up to, and they update live as people react.
Disabled reactions don't count.

**Hot** adds the comment count to the points and weighs the sum on a log scale
against age, so ten times the engagement buys a topic about 12.5 hours of
freshness. A brilliant topic from last month politely makes room for today's.

## Comments

Topic comments look exactly like blog and news comments - they all use the
Content Engine's shared [comment section](/docs/content-engine/comments-api#contentcomments).
Each top-level comment is a card, and its replies sit inside it in the order
they were written, each naming whom it answers. Replies go up to six levels
deep. Every comment shows its points next to its reactions, and comments by
the topic's starter carry an **Author** badge.

Comments come in posting order, like a classic forum. Above them, readers can
switch to **Newest** or **Most points**; only whole conversations move. Edited
comments get an **edited** link with the edit history, and new comments show up
live while the topic is open.

The forum index, forum and topic pages are cached for a minute and refreshed in the
background. Edit buttons and the comment box load in the browser, so every
visitor gets the same cached page. The comment editor itself waits for a click on
**Write a comment…**, so readers who only read never download it.

Topic and comment counts are cached too when Redis is configured (`REDIS_URL`).
Any new, published, hidden, moved or deleted topic or comment expires them on
the spot, and a five-minute limit catches anything that changed behind the
forum's back, such as a row edited by hand. Topic lists leave out the topic body,
so `GET /api/@vitnode/forum/content/topics` returns titles, slugs and dates only -
read one topic for its body. Topic pages set a canonical URL and
`DiscussionForumPosting` structured data with the comment count.

Topics also have [delivery](/docs/content-engine/seo): a renamed topic
redirects its old address to the new one, and
`/api/@vitnode/forum/content/topics/delivery/sitemap` lists every public topic
for your `sitemap.xml`. Topics waiting for approval never appear there, in
search or in any list - until a moderator says yes, they don't exist for
anyone but their author.

Topics and comments show up in [search](/docs/dev/search), on `/discover` and
on their authors' profile timelines. A comment is headed by its topic's title
and stays out of public results while its topic is not public - see
[Borrow the title from a related record](/docs/content-engine/search#borrow-the-title-from-a-related-record).
Upgrading a forum that already has posts? Rebuild the index once in
**Debug Panel → Search** (`/admin/core/debug/search`).

## Choose who publishes straight away

By default every member's topic and comment goes live immediately and authors can
edit their posts for as long as they like. Change that per forum in the forum's
**Publishing** settings - for example, require approval for new topics in
**Announcements**, or let authors edit comments for one hour only. A forum
inherits from its parent until you override a value. See
[Container policies](/docs/content-engine/container-policies) for every option.

When a post needs approval, the author sees "Waiting for a moderator", and the
post appears on `/forum/me/pending`. Moderators with the **Approve** permission for
that forum review it in ModCP. See [Approvals](/docs/content-engine/approvals).

## Grant moderators a forum

AdminCP only manages the forums themselves. Topics and comments live on the
public forum: authors edit their own, and moderators step in right there or in
ModCP.

Moderator permissions for topics and comments are scoped by forum. Give a
moderator role **Edit** and **Approve** on **Topics** and **Comments**, and pick
the forums it covers - a single forum, or a forum and everything below it. See
[Scoped permissions](/docs/dev/moderation/scoped-permissions).
