## The value

```ts
type EmojiIconValue =
  { type: 'emoji'; value: string } | { type: 'icon'; value: string }
```

An emoji value is the character (`🚀`). An icon value is a kebab-case
[Lucide](https://lucide.dev/icons) name (`shield-check`), readable in the
database and portable to any Lucide renderer.

For storage, serialize it to `emoji:🚀` or `icon:rocket`. It fits a
`varchar(64)` column.

```ts
import {
  parseEmojiIcon,
  serializeEmojiIcon,
} from '@vitnode/core/lib/emoji-icon'

serializeEmojiIcon({ type: 'icon', value: 'rocket' })
parseEmojiIcon('emoji:🚀')
parseEmojiIcon('icon:../../etc/passwd')
```

These return `"icon:rocket"`, `{ type: 'emoji', value: '🚀' }` and `undefined`.
`parseEmojiIcon` is also the validator: anything that isn't exactly one emoji or
one icon name comes back `undefined`.

<Callout type="warn" title="Validate on the server too">
  The picker only produces valid values. A request body can say anything, so
  parse it before you write it:

```ts
prefix: serializeEmojiIcon(parseEmojiIcon(body.prefix)) || null
```

</Callout>

## Rendering a stored value

<Preview name="emoji-icon-picker-render" />

`EmojiIcon` renders a parsed value: a glyph for an emoji, an SVG for an icon.
An invalid value renders nothing.

```tsx
import { EmojiIcon } from '@vitnode/core/components/ui/emoji-icon'

;<EmojiIcon value={parseEmojiIcon(role.prefix)} />
```

Only icon names? Use [`DynamicIcon`](/docs/ui/icons#icons-by-name). Icons
rendered on the server arrive in the first HTML, and the browser never ships the
whole icon library. That needs one line in `getRouter()`, already in the
scaffold:

```tsx title="src/router.tsx"
import { setupLucideIconSsr } from '@vitnode/core/tanstack/icons'

setupLucideIconSsr({ router })
```

Without it, `DynamicIcon` still works but loads icons in the browser after the
page renders.

Both are `aria-hidden`, since they decorate nearby text. An icon-only control
needs its own `aria-label`.

## Role prefixes

A role's **Prefix** field (General tab of its edit dialog) uses this picker. The
prefix shows before the role name and before every member's name wherever
`RoleFormat` or `UserFormat` renders. It arrives as `role.prefix`
(`null | string`), and both components parse it for you.

```tsx
<UserFormat format user={user} />
```

## Performance and keyboard

- Only the trigger ships with your page. Emoji data loads when the popover
  opens, and the ~1750 icons load only when someone opens the **Icon** tab.
- The icon grid is virtualized, so its size doesn't hurt scrolling.
- The grid is one tab stop. Arrows move (up and down jump a row),
  <kbd>Home</kbd> / <kbd>End</kbd> go to the row's ends, <kbd>Enter</kbd> or
  <kbd>Space</kbd> picks.
- The emoji picker here and in the editor toolbar share grid size, search and
  skin tone switch.

Other `button` props go to the trigger. `AutoFormEmojiIcon` takes the same props
except `value` and `onChange`.
