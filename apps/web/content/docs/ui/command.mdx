## Usage

```ts
import {
  Command,
  CommandEmpty,
  CommandGroup,
  CommandInput,
  CommandItem,
  CommandList,
  CommandSeparator,
  CommandShortcut,
} from '@vitnode/core/components/ui/command'
```

```tsx
<Command>
  <CommandInput placeholder="Type a command or search..." />
  <CommandList>
    <CommandEmpty>No results found.</CommandEmpty>
    <CommandGroup heading="Suggestions">
      <CommandItem>Calendar</CommandItem>
      <CommandItem>Search Emoji</CommandItem>
    </CommandGroup>
  </CommandList>
</Command>
```

Type and the list filters itself, best matches first. Empty groups hide. Built
on [cmdk](https://cmdk.paco.me), so every cmdk prop works.

## Groups, icons and shortcuts

`CommandGroup` takes a `heading`, and `CommandSeparator` splits groups. Icons go
first and are sized for you. `CommandShortcut` is only a label: bind the keys
yourself.

```tsx
<CommandGroup heading="Settings">
  <CommandItem>
    <UserIcon />
    <span>Profile</span>
    <CommandShortcut>⌘P</CommandShortcut>
  </CommandItem>
</CommandGroup>
<CommandSeparator />
```

`CommandEmpty` shows only when nothing matches. Make it kind.

## Selecting items

`onSelect` fires on click and <kbd>Enter</kbd>. `disabled` keeps an item
visible but skipped. Items match by their text: add `value` when the text isn't
unique, and `keywords` for other names people might type.

```tsx
<CommandItem onSelect={() => router.navigate({ to: '/settings' })}>
  Settings
</CommandItem>
<CommandItem keywords={['theme', 'night']} value="toggle-dark-mode">
  Toggle dark mode
</CommandItem>
```

## Dialog

<Preview name="command-dialog" />

`CommandDialog` wraps a `Command` in a [Dialog](/docs/ui/dialog) with a
screen-reader-only title and description. Control it with `open` and
`onOpenChange`, and bind a shortcut yourself.

```tsx
const [open, setOpen] = React.useState(false)

React.useEffect(() => {
  const handleKeyDown = (event: KeyboardEvent) => {
    if (event.key.toLowerCase() !== 'j') return
    if (!event.metaKey && !event.ctrlKey) return
    if (event.altKey || event.shiftKey || event.defaultPrevented) return

    event.preventDefault()
    setOpen(prev => !prev)
  }

  window.addEventListener('keydown', handleKeyDown)

  return () => window.removeEventListener('keydown', handleKeyDown)
}, [])

<CommandDialog onOpenChange={setOpen} open={open}>
  <Command>
    <CommandInput placeholder="What do you need?" />
    <CommandList>...</CommandList>
  </Command>
</CommandDialog>
```

<Callout title="Why ⌘J and not ⌘K?">
  The docs search and the AdminCP already own <kbd>⌘K</kbd> / <kbd>Ctrl+K</kbd>,
  so the demo uses <kbd>⌘J</kbd> / <kbd>Ctrl+J</kbd>. Pick a free key and remove
  the listener on unmount. Inside the open palette <kbd>Ctrl+J</kbd> moves down
  a row, so <kbd>Escape</kbd> is the way out.
</Callout>

Show the shortcut next to the trigger with [`Kbd`](/docs/ui/kbd), like the demo.

## Your own filtering

<Preview name="command-async" />

Searching an API? Set `shouldFilter={false}` and render what your query returns.
The AdminCP search works this way.

```tsx
<Command label="Search members" shouldFilter={false}>
  <CommandInput onValueChange={setSearch} value={search} />
  <CommandList>
    {members.map((member) => (
      <CommandItem key={member.id} value={member.id}>
        {member.name}
      </CommandItem>
    ))}
  </CommandList>
</Command>
```

## Accessibility

- The input is a `combobox` and the list a `listbox`, so screen readers announce
  the highlighted option.
- <kbd>↑</kbd> / <kbd>↓</kbd> move, <kbd>Home</kbd> / <kbd>End</kbd> jump to the
  ends, <kbd>Enter</kbd> selects. `loop` wraps at the edges.
- <kbd>Ctrl+N</kbd> / <kbd>Ctrl+J</kbd> and <kbd>Ctrl+P</kbd> /<kbd>Ctrl+K</kbd>
  also move. Turn them off with `vimBindings={false}`.
- Give a standalone `Command` a `label` so the input has a name.
  `CommandDialog` traps focus and closes on <kbd>Escape</kbd>.
