A **block** is a page section somebody can place, in an order they choose: a hero, a paragraph of prose, a call to action, "the six newest articles". A plugin defines it once - the fields it holds and the React component that renders it - and every content type in the installation can offer it.

```text
Plugin
  ↓ defines blocks
Block Registry
  ↓ allowed by a blocks() field
Content record
  ↓
ContentRenderer
```

## What a block is made of

| Part | What it is |
| :--- | :--- |
| **Id** | `hero`, written without a namespace. The registry prefixes the plugin's own, so it is stored as `core:hero`. |
| **Fields** | Content Engine field descriptors - the same `field.text()`, `field.enum()` and friends a content type uses. There is no second schema system. |
| **Component** | One public React component. It receives data the block's own schema has already validated. |
| **Schema** | Derived from `fields`. You never write it. |

## What a block is not

A block is **not** a content type. It has no table, no id of its own in the database, no permissions and no API routes. It is a value that lives inside a record - which is exactly why re-ordering a page is one `UPDATE` and not a migration.

<Callout title="Visual editing comes later">
  This is the runtime and data foundation. Blocks are defined, registered, stored, validated and rendered - there is no editor, no drag and drop, and no block picker yet. Content Zones and the Visual Editor build on top of everything on these pages without changing any of it.
</Callout>

## How blocks reach an application

Nothing is scanned and nothing is queried. A plugin exports a `blocks` module; VitNode's Vite plugin sees it and writes `src/blocks.gen.ts`, which builds the registry and registers it.

```ts title="src/blocks.gen.ts (generated)"
import { buildBlockRegistry, setBlockRegistry } from "@vitnode/core/blocks"

import { blocks as blocks0 } from "@vitnode/core/blocks/built-in"
import { blocks as blocks1 } from "@vitnode/example/blocks"

export const pluginBlocks = [blocks0, blocks1]

export const blocksRegistry = buildBlockRegistry(pluginBlocks)

setBlockRegistry(blocksRegistry)
```

Installing a plugin is the whole registration step. Removing it takes its blocks with it, and a page that still references one keeps rendering everything else - see [Rendering](/docs/dev/blocks/rendering).

## Blocks that ship with core

| Id | What it renders |
| :--- | :--- |
| `core:hero` | A page heading with an optional eyebrow, lead paragraph and one link. |
| `core:text` | Plain paragraphs of prose. Blank lines separate paragraphs; nothing is parsed as markup. |
| `core:cta` | A short call to action with one link. |
