This page takes you from an empty folder to a running VitNode app, with you signed in to the AdminCP as its administrator. It is the first lesson of the beginner path; the next one creates a plugin inside this app.

## Before you begin

- **Node.js** `22.18` or newer in the 22 line, `24.11` or newer in the 24 line, or `26` and later. The generator and every generated package refuse older versions.
- **A package manager:** pnpm, bun or npm.
- **PostgreSQL.** The easiest local option is Docker, which the generator can configure for you. Your own PostgreSQL server works too.

<Steps>

<Step>

### Scaffold the app

Run the generator from the folder that should contain your project:

<Tabs groupId="package-manager" persist items={["bun", "pnpm", "npm"]} label="Create a VitNode app">

```bash tab="bun"
bun create vitnode-app@canary
```

```bash tab="pnpm"
pnpm create vitnode-app@canary
```

```bash tab="npm"
npm create vitnode-app@canary
```

</Tabs>

It asks for a project name (default `my-vitnode`), then these questions. The recommended answers set you up for the rest of the beginner path:

| Question              | Recommended                                 | Why                                                                                                                                           |
| --------------------- | ------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| Package manager       | the one you use                             | The generator offers only the managers you have installed.                                                                                    |
| App type              | **Single App**                              | One TanStack Start app with the Hono API mounted at `/api`. **Monorepo App** splits web and API into two apps; **Only API** has no front end. |
| Use Turborepo?        | **Yes**                                     | Required to create plugins. A Monorepo App always gets it, so the generator skips the question.                                               |
| Oxlint & Oxfmt?       | your choice                                 | Adds lint and format scripts.                                                                                                                 |
| Docker container?     | **Yes**, unless you run PostgreSQL yourself | Adds `docker-compose.yml` with PostgreSQL 17 and Redis on `127.0.0.1`.                                                                        |
| Git repository?       | your choice                                 |                                                                                                                                               |
| Install dependencies? | **Yes**                                     | Installs packages and generates the first migrations.                                                                                         |

With Turborepo, the app lives in `apps/web` (plus `apps/api` for a Monorepo App) and your plugins will go in `plugins/`. Without it, the app sits at the project root and you cannot create plugins later.

</Step>

<Step>

### Open the project

<Tabs groupId="package-manager" persist items={["bun", "pnpm", "npm"]} label="Open the project">

```bash tab="bun"
cd my-vitnode
```

```bash tab="pnpm"
cd my-vitnode
```

```bash tab="npm"
cd my-vitnode
```

</Tabs>

Run every command in this lesson, and in the lessons after it, from this folder. If you answered **No** to "Install dependencies?", install them now with `bun install`, `pnpm install` or `npm install`.

</Step>

<Step>

### Configure the environment

The app reads its settings from `.env`. A Monorepo App already has `apps/web/.env`; a Single App ships only `.env.example`. Copy it next to itself:

```bash title="Single App with Turborepo"
cp apps/web/.env.example apps/web/.env
```

For a Monorepo App / Single API:

```bash title="Monorepo App / Single API"
cp apps/api/.env.example apps/api/.env
```

The defaults match the Docker services:

- PostgreSQL at `postgresql://root:root@localhost:5432/vitnode`. Using your own PostgreSQL? Change `POSTGRES_URL` to its connection string.
- Redis at `redis://localhost:6379` with the password `root`. Redis is optional. Delete `REDIS_URL` to run without it, and VitNode falls back to an in-process cache.

</Step>

<Step>

### Start PostgreSQL

With Docker, start the database and Redis in the background:

<Tabs groupId="package-manager" persist items={["bun", "pnpm", "npm"]} label="Start local services">

```bash tab="bun"
bun run docker:dev
```

```bash tab="pnpm"
pnpm docker:dev
```

```bash tab="npm"
npm run docker:dev
```

</Tabs>

Without Docker, make sure the server in `POSTGRES_URL` is running and the database exists.

</Step>

<Step>

### Start the development server

<Tabs groupId="package-manager" persist items={["bun", "pnpm", "npm"]} label="Start the development server">

```bash tab="bun"
bun run dev
```

```bash tab="pnpm"
pnpm dev
```

```bash tab="npm"
npm run dev
```

</Tabs>

Before the server starts, `dev` builds your plugins, generates any pending migrations, applies them and seeds the default roles. You never run migrations by hand on this path. When it is ready, it prints the addresses:

```txt
  Web       http://localhost:3000
  AdminCP   http://localhost:3000/admin
  API       http://localhost:3000/api
```

</Step>

<Step>

### Create the administrator account

VitNode has no installer. The **first account that registers becomes the administrator**. It gets the root Administrator role and a verified email. Every later account is a regular member.

Open `http://localhost:3000/register` and create your account. Then open `http://localhost:3000/admin` and sign in with the same email and password. The AdminCP has its own sign-in, separate from the site's.

</Step>

</Steps>

## Check the result

- `http://localhost:3000` shows the public site, and the header has your avatar.
- `http://localhost:3000/admin` shows the AdminCP dashboard after you sign in.
- **Staff → Administrators** in the AdminCP lists the **Administrator** role as unrestricted.

If `dev` stops with a database error, PostgreSQL is not reachable at `POSTGRES_URL`. Check that the containers are up (`docker ps`) or that your own server accepts the connection.
