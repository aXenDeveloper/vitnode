Every VitNode site serves `/robots.txt` and `/sitemap.xml` out of the box. Admins decide what crawlers may visit and which pages the sitemap lists in **AdminCP → System → SEO**, so a staging site can hide from Google and a forum can keep AI scrapers out without touching a file.

## What you get without configuring anything

| URL                        | What it serves                                                                                   |
| -------------------------- | ------------------------------------------------------------------------------------------------ |
| `/robots.txt`              | `Disallow` for the private areas (`/admin`, `/settings`, `/modcp`, `/notifications`, `/files`) in every language, plus a `Sitemap:` line |
| `/sitemap.xml`             | A sitemap index with one entry per file of every source that has public pages                    |
| `/sitemaps/{source}-{n}.xml` | One file of a source, such as `/sitemaps/blog_post-1.xml`, with `hreflang` alternates for localized pages |

The sitemap lists the home page, the listing pages plugins register (`/blog`, `/forum`) and every published record of a [content type with `delivery.sitemap`](/docs/content-engine/seo#sitemap). Only what a guest may read gets in: drafts, scheduled, hidden, `noIndex` and members-only records stay out. URLs use `VITNODE_WEB_URL` as the origin, so set it to your public address in production.

Apps created with `create-vitnode-app` already have the three route files. An app made earlier needs them added once, as [Add the routes to an older app](#add-the-routes-to-an-older-app) shows.

## Change what crawlers may visit

<Steps>

<Step>

### Open the SEO settings

Go to **AdminCP → System → SEO**. Viewing it takes the **SEO → View** staff permission, and saving takes **SEO → Manage**.

</Step>

<Step>

### Pick the rules on General & robots.txt

- **Allow search engines to index this site**: turn it off on a staging or private site. `/robots.txt` then answers `Disallow: /` to everyone and the sitemaps answer `404`. Pages already in search results drop out over the following weeks, so leave it on for a live site.
- **Block AI training crawlers**: adds one group that disallows the bots collecting pages for AI training, such as GPTBot, ClaudeBot, Google-Extended, CCBot and Bytespider. Search engines and assistants that fetch a page for a reader keep working.
- **Custom robots.txt rules**: lines appended to the end of the file as written, for example a `Crawl-delay` for one bot.

The **Live preview** below the fields shows the exact file `/robots.txt` will serve, and changes as you type. Select **Save** to publish it.

/>

</Step>

<Step>

### Tune the sitemaps

Open the **Sitemaps** tab. **Enable XML sitemaps** switches `/sitemap.xml` on or off, and **URLs per sitemap file** (100 to 50,000, default 10,000) sets how many URLs each file holds. A source with 25,000 URLs at the default size gets three files.

The **Sources** table lists everything that adds pages, with its URL count and a link to its first file. Turn off a source's switch to drop it from `/sitemap.xml` at once; its files answer `404` until you turn it back on. Sources a plugin adds later start switched on.

</Steps>

Each save writes an entry to the [activity log](/docs/dev/audit-logs) and emits [`seo.settings.updated`](/docs/dev/events/built-in-events#seo-events).

## While the site is offline

When [site offline mode](/docs/dev/site-offline-mode) is on, `/robots.txt` and the sitemaps answer `503` with `Retry-After` set to the opening time. Crawlers read that as "come back later" and keep the pages they already indexed, which a `Disallow: /` would not do. The AdminCP preview says so above the file.

## Caching

`/robots.txt` is cached for 5 minutes, so turning indexing off reaches crawlers quickly. `/sitemap.xml` and its files are cached for an hour (`public, max-age=3600, s-maxage=3600, stale-while-revalidate=86400`), which is often enough for crawlers and spares the database. A CDN in front of the site keeps its copy for the same time.

## Add the routes to an older app

The files live in the web app, at the root of the site rather than under `/api`. Create the three route files, then delete any static `public/robots.txt` or `public/sitemap.xml`, because a static file wins over a route.

```ts title="src/routes/robots[.]txt.ts"
import { createFileRoute } from "@tanstack/react-router";
import { robotsTxtHandler } from "@vitnode/core/tanstack/seo/server";

export const Route = createFileRoute("/robots.txt")({
  server: { handlers: { GET: robotsTxtHandler } },
});
```

```ts title="src/routes/sitemap[.]xml.ts"
import { createFileRoute } from "@tanstack/react-router";
import { sitemapIndexHandler } from "@vitnode/core/tanstack/seo/server";

export const Route = createFileRoute("/sitemap.xml")({
  server: { handlers: { GET: sitemapIndexHandler } },
});
```

```ts title="src/routes/sitemaps.$file.ts"
import { createFileRoute } from "@tanstack/react-router";
import { sitemapFileHandler } from "@vitnode/core/tanstack/seo/server";

export const Route = createFileRoute("/sitemaps/$file")({
  server: { handlers: { GET: sitemapFileHandler } },
});
```

The handlers call the API in-process in a single app, and over `VITNODE_API_URL` when the API runs on its own. These three paths are never locale-prefixed: `/pl/robots.txt` redirects to `/robots.txt`.

## Check the result

Open `/robots.txt` and `/sitemap.xml` in the browser, or with `curl`:

```bash
curl -i http://localhost:3000/robots.txt
curl http://localhost:3000/sitemap.xml
```

```xml
<?xml version="1.0" encoding="UTF-8"?>
<sitemapindex xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
  <sitemap>
    <loc>http://localhost:3000/sitemaps/static-1.xml</loc>
  </sitemap>
  <sitemap>
    <loc>http://localhost:3000/sitemaps/blog_post-1.xml</loc>
    <lastmod>2026-11-23T20:18:25.940Z</lastmod>
  </sitemap>
</sitemapindex>
```

Then turn off **Allow search engines to index this site**, save, and request both again: `/robots.txt` answers `Disallow: /` and `/sitemap.xml` answers `404`. Submit `https://your-site/sitemap.xml` in Google Search Console and Bing Webmaster Tools once the site is live.
