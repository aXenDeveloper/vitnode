title: Fetcher
description: Type-safe, RPC-style calls to your own Hono API.

The VitNode fetcher is a typed, RPC-style wrapper around `fetch`. You import an
API module as a **type**, name a path and a method on it, and TypeScript checks
the params, the body and the response - end to end, with no code generation step.

## Which one to import

Three entry points, and the difference between them is **whose request they are
part of**:

import { TypeTable } from "fumadocs-ui/components/type-table";

<TypeTable

## Getting started

Import the module as a type and turn it into a reference with `clientModule`, so
none of the API's server code follows it into the bundle:

```ts
import type { usersModule } from "@vitnode/core/api/modules/users/users.module";

import { clientModule, fetcherClient } from "@vitnode/core/lib/fetcher-client";

const usersModuleRef = clientModule<typeof usersModule>("@vitnode/core");
```

Then make the call:

```ts
const response = await fetcherClient(usersModuleRef, {
  path: "/session",
  method: "get",
  module: "users",
});

if (response.ok) {
  const data = await response.json();
}
```

The fetcher returns a standard `Response`, just like native `fetch`. Paths,
methods and the parsed JSON are all inferred from the module's route definitions.

<Callout type="warn" title="Declare a `200` with `content`">
  `res.json()` is typed from the route's declared responses. A route that
  declares a non-200 response with no `content` (a bare `401`, say) widens the
  union to `unknown`, and every caller loses its types.
</Callout>

## In a query

The usual shape: one exported `queryOptions`, with the request inside it.

```ts title="announcements-query.ts"
import { queryOptions } from "@tanstack/react-query";
import { RECORD_STALE_TIME } from "@vitnode/core/lib/query-freshness";

export const announcementsQuery = () =>
  queryOptions({
    queryFn: async () => {
      const response = await fetcherClient(announcementsModuleRef, {
        method: "get",
        module: "announcements",
        path: "/",
      });

      if (!response.ok) throw new Error("Failed to load announcements");

      return await response.json();
    },
    queryKey: ["announcements"],
    staleTime: RECORD_STALE_TIME,
  });
```

The route's `loader` warms it with `ensureQueryData` and the component reads it
back with `useSuspenseQuery`. See [Data
loading](/docs/dev/tanstack/data-loading) and [Cache](/docs/dev/cache).

## Advanced features

### Path prefixing

When working with nested modules, add `prefixPath` to reach a mounted subtree:

```ts
const response = await fetcherClient(categoriesAdminModuleRef, {
  // [!code ++]
  prefixPath: '/admin', // Adds prefix to the path
  path: '/categories',
  method: 'post',
  module: 'categories',
  args: {
    body: {
      name: 'Technology',
      description: 'Tech-related articles',
    },
  },
});

// This will make a request to: /admin/categories
```

### Public data on the server

`fetcherServer` forwards the incoming request's cookies, which is exactly what
you want for anything per-visitor and exactly what you do not want for anything
shared. For a response that is the same for everyone, reach for `coreFetcher`:

```ts
import { coreFetcher } from "@vitnode/core/lib/fetcher/core";

const announcements = async (locale: string) => {
  const response = await coreFetcher(announcementsModuleRef, {
    args: { query: { lang: locale } },
    method: "get",
    module: "announcements",
    path: "/",
  });

  return await response.json();
};
```

### Cookie management

Sign-in is the case that needs a server function: the API answers with a
`Set-Cookie`, and only something running inside this request can copy it onto
*this* document's response.

```ts title="apps/web/src/lib/auth.ts"
import { createServerFn } from "@tanstack/react-start";
import { signInInputSchema } from "@vitnode/core/tanstack/auth";
import { signInOnApi } from "@vitnode/core/tanstack/auth/server";

export const signInFn = createServerFn({ method: "POST" })
  .validator(signInInputSchema)
  .handler(async ({ data }) => await signInOnApi(data));
```

<Callout type="info" title="Cookie handling">
  Cookies are saved only for responses with a 2xx status code. A refusal never
  writes one.
</Callout>

See [Server functions](/docs/dev/tanstack/server-functions) for when one is
warranted - which is rarer than it looks.
