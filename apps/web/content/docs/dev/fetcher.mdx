<Callout type="info" title="Use this by default">
  In a TanStack Start app, import `fetcher` from
  `@vitnode/core/tanstack/fetcher`. The same call works during SSR and browser
  navigation.
</Callout>

During SSR, it forwards the visitor's request to the API. In the browser, it
calls `/api/*` directly. You do not need to write `createIsomorphicFn()`.

## Use the universal fetcher

<Steps>

<Step>

### Create a typed module reference

Import the API module as a type, then give VitNode its plugin id at runtime.

```ts
import type { usersModule } from "@vitnode/core/api/modules/users/users.module"

import { clientModule } from "@vitnode/core/tanstack/fetcher"

const users = clientModule<typeof usersModule>("@vitnode/core")
```

</Step>

<Step>

### Make the request

```ts
import { fetcher } from "@vitnode/core/tanstack/fetcher"

export const fetchDevices = async ({ signal }: { signal?: AbortSignal } = {}) => {
  const response = await fetcher(users, {
    method: "get",
    module: "users",
    options: { signal },
    path: "/devices",
  })

  if (!response.ok) {
    throw new Error(`The devices API answered ${response.status}.`)
  }

  return await response.json()
}
```

Use this function in your TanStack Query options. See
[Data Loading](/docs/dev/data-loading) for loading it in a route and component.

</Step>

</Steps>

## Exceptions

<Tabs items={["Server only", "Outside TanStack Start"]}>
  <Tab value="Server only">

Use the explicit server fetcher only when the server itself needs to handle the
request: a server function, cookie relay, cron/job, secret, or custom API
origin.

```ts
import { usersModule } from "@vitnode/core/api/modules/users/users.module"
import { fetcher } from "@vitnode/core/tanstack/fetcher/server"

const response = await fetcher(usersModule, {
  allowSaveCookies: true,
  args: { body: { email, password } },
  method: "post",
  module: "users",
  path: "/sign_in",
})
```

<Callout type="warn" title="Keep it server-only">
  Put code that imports this fetcher in a `*.server.ts` file, or call it only
  from a server function.
</Callout>

  </Tab>

  <Tab value="Outside TanStack Start">

For framework-neutral shared browser code, or a host that is not TanStack Start,
use `fetcherClient`.

```ts
import { clientModule, fetcherClient } from "@vitnode/core/lib/fetcher-client"

const comments = clientModule<typeof commentsModule>("@vitnode/blog")

const response = await fetcherClient(comments, {
  args: { body: { text } },
  method: "post",
  module: "comments",
  path: "/",
})
```

  </Tab>
</Tabs>

## What the types do

- `method`, `module`, and `path` are always required.
- `args` is required when the route declares a body, params, or query.
- TypeScript infers the valid route, arguments, response status, and JSON body.

Generated Content Engine modules have no static module type, so use
`rawFetcher` for them instead.
