## Basic usage

Pass the namespace of the message to `useTranslations`:

```tsx
import { useTranslations } from "use-intl";

export const ExampleComponent = () => {
  const t = useTranslations("welcome.home"); // [!code highlight]

  return <div>{t("hello")}</div>;
};
```

That is the same hook everywhere a React tree renders - during SSR and in the
browser, in the app and in a plugin. There is no second, async variant.

<Callout type="info" title="Outside React">
  In an API handler, an email template or anything else with no React context,
  build a translator instead: `createTranslator({ locale, messages })` from
  `use-intl`. See [Server-side](/docs/dev/i18n/server).
</Callout>

## Example of usage

### Dynamic values

```json title="en.json"
"message": "Hello {name}!"
```

```ts
t("message", { name: "Jane" }); // "Hello Jane!"
```

### Pluralization

```json title="en.json"
"message": "You have {count, plural, one {# message} other {# messages}}"
```

```ts
t("message", { count: 1 }); // "You have 1 message"
t("message", { count: 2 }); // "You have 2 messages"
```

### Rich text

```json title="en.json"
{
  "message": "Please refer to <guidelines>the guidelines</guidelines>."
}
```

```tsx
// Returns `<>Please refer to <a href="/guidelines">the guidelines</a>.</>`
t.rich("message", {
  guidelines: (chunks) => <a href="/guidelines">{chunks}</a>
});
```

## Message syntax

Messages are [ICU MessageFormat](https://unicode-org.github.io/icu/userguide/format_parse/messages/),
and `use-intl` implements it. Its
[message documentation](https://next-intl.dev/docs/usage/messages) covers the
full syntax - `use-intl` is the framework-agnostic core that library is built on,
so everything about the *messages* applies verbatim.
