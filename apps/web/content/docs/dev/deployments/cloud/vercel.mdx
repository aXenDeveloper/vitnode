## Limitations

Some features of Vitnode are not supported on Vercel due to its serverless architecture. These include:

- Self-hosted static files
- WebSockets

## Requirements

- A Vercel account
- Your project pushed to a Git repository (GitHub, GitLab, or Bitbucket)
- PostgreSQL database (can be hosted on Supabase)

## Deployment Guide

<Steps>
<Step>

### Generate migrations, and commit them

Locally, write the migration files for your current schema and stop - no
connection, no apply:

import { Tab, Tabs } from 'fumadocs-ui/components/tabs';

<Tabs groupId='package-manager' persist items={['bun', 'pnpm', 'npm']} label='Generate Migrations'>

```bash tab="bun"
bun db:migrate --generate
```

```bash tab="pnpm"
pnpm db:migrate --generate
```

```bash tab="npm"
npm run db:migrate -- --generate
```

</Tabs>

Commit the files it writes. The build does not generate migrations, and it must
not: a build with no database connection cannot diff a schema.

</Step>
<Step>

### Apply them as a deployment step

Migrating is **not** automatic in production, deliberately: a horizontally scaled
deployment would have every replica racing to migrate the same database on boot.
Run it once, as its own step, before the new version starts serving:

```bash
pnpm db:migrate
```

`start` never migrates. See [Database](/docs/dev/database#in-production).

</Step>
<Step>

### Upload your project / changes to Git

Make sure your Vitnode project is pushed to a Git repository.

</Step>
<Step>

### Sign in to Vercel

Go to [Vercel](https://vercel.com/) and sign in.

</Step>
<Step>

### Create a New Project

Click on "New Project" in your Vercel dashboard. Select the repository where your Vitnode project is hosted.

</Step>
</Steps>
