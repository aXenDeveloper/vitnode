title: Content Delivery & SEO
description: Serve a content type at a public URL - slug redirect history, canonical links, hreflang, SEO metadata and XML sitemaps.

---

Turn on `delivery` and a content type gets a public URL contract: a canonical
path, 308 redirects for every slug it used to have, `hreflang` alternates for its
published translations, ready-made SEO metadata, and a paginated sitemap feed.

The engine produces the *answers*. Your route renders them - which keeps the
whole thing framework-neutral: the same three HTTP endpoints serve a page in this
app, in a separately deployed frontend, or in a static build.

## Prerequisites

A content type with `publicApi` enabled and exactly one exposed slug field.
Delivery is refused without one - there is no canonical path to build, no
redirect to issue and no sitemap entry to emit.

---

<Steps>

<Step>
### Enable delivery in the definition

```ts title="src/content/article.ts"
export const articleContentType = defineContentType({
  id: "example.article",
  tableName: "example_articles",
  publication: true,
  editorial: true,
  publicApi: {
    enabled: true,
    path: "articles",
    fields: ["title", "slug", "excerpt", "publishedAt"],
  },
  delivery: { // [!code ++]
    enabled: true, // [!code ++]
    redirects: { enabled: true }, // 308s on slug rename // [!code ++]
    seo: { // [!code ++]
      titleField: "title", // [!code ++]
      descriptionField: "excerpt", // [!code ++]
    }, // [!code ++]
    sitemap: { enabled: true, changeFrequency: "weekly", priority: 0.8 }, // [!code ++]
  }, // [!code ++]
  fields: {
    title: field.text({ required: true }),
    slug: field.slug({ from: "title" }),
    excerpt: field.textarea({ nullable: true }),
  },
});
```

<Callout type="warn" title="`redirects` needs `editorial`">
  Slug history has to be written in the same transaction as the slug change, its
  version and its revision - and only the editorial mutation path owns that
  transaction. Delivery without `redirects` (canonical URLs, SEO, alternates,
  sitemap) works on its own.
</Callout>
</Step>

<Step>
### What you get on the API

Registering the content type's public module mounts three routes beside the
ordinary public reads:

```http
GET /api/{pluginId}/content/{publicApi.path}/delivery/resolve/{slug}
GET /api/{pluginId}/content/{publicApi.path}/delivery/item/{id}
GET /api/{pluginId}/content/{publicApi.path}/delivery/sitemap
```

`resolve` is the one a page calls. It answers `200` with a discriminated union:

| `type`        | What it means                                                |
| ------------- | ------------------------------------------------------------ |
| `"content"`   | The record is here. Canonical path, alternates, hreflang, SEO |
| `"redirect"`  | This slug was retired. `location` and `status` (308)          |
| `"not_found"` | Nothing here - **a `200` with a body**, not a `404`           |

Three arms rather than a nullable object, because the three outcomes need three
different responses and a client that had to guess would eventually redirect to
`undefined`.
</Step>

<Step>
### Render it in a route

An ordinary TanStack Start route: resolve in the `loader`, act on the arm, and
build the `<head>` from what came back.

```tsx title="apps/web/src/routes/_main/articles.$slug.tsx"
import { createFileRoute, notFound, redirect } from "@tanstack/react-router";

import { pageHead } from "#/lib/page-head";
import { resolveArticleDelivery } from "#/lib/articles";

export const Route = createFileRoute("/_main/articles/$slug")({
  loader: async ({ params }) => {
    const delivery = await resolveArticleDelivery(params.slug);

    if (delivery.type === "redirect") {
      throw redirect({ href: delivery.location, statusCode: delivery.status });
    }

    if (delivery.type === "not_found") throw notFound();

    return delivery;
  },
  head: ({ loaderData }) =>
    pageHead({
      title: loaderData?.seo.title ?? undefined,
      description: loaderData?.seo.description ?? undefined,
      robots:
        loaderData?.robots?.index === false
          ? "noindex, nofollow"
          : "index, follow",
    }),
  component: ArticlePage,
});

const ArticlePage = () => {
  const delivery = Route.useLoaderData();

  return (
    <article className="container mx-auto flex max-w-2xl flex-col gap-4 p-4">
      <h1 className="text-3xl font-semibold tracking-tight text-balance">
        {delivery.seo.title}
      </h1>
      <p className="text-muted-foreground leading-relaxed text-pretty">
        {delivery.seo.description}
      </p>
    </article>
  );
};
```

<Callout type="info" title="`href`, not `to`">
  `delivery.location` is a path the engine already built - locale segment
  included, for a localized content type. `href` sends the browser there
  verbatim; `to` would name a route in the tree and get the locale prefix written
  in a second time.
</Callout>

<Callout type="warn" title="Write `head` after `loader`">
  `loaderData`'s type is inferred from `loader` in the same object literal, and
  TypeScript reads members in order. Put `head` first and `loaderData` is `never`.
</Callout>

<Callout type="info" title="A plugin does the same thing, as data">
  A plugin route declares the URL in its manifest and puts the same `load` and
  `head` in `definePluginRoute`. See [Route
  Manifest](/docs/dev/plugins/route-manifest).
</Callout>
</Step>

</Steps>

## What the resolution carries

<Callout type="info" title="Everything below is framework-neutral">
  `canonicalPath` and every alternate are **relative paths**, never absolute
  URLs. A definition lives in source control and is deployed to a preview domain,
  a staging domain and production, so an origin baked into it would be wrong in
  two of the three. `contentDeliveryUrl({ origin, path })` adds one when a caller
  has one to add.
</Callout>

- **`canonicalPath`** - the record's one true path, locale segment included for a
  localized content type.
- **`alternates`** and **`hreflang`** - one entry per genuinely published
  translation. A fallback is *not* an alternate: it has no URL of its own, so
  listing it would announce a page that answers 404.
- **`seo`** and **`openGraph`** - `{ title, description }`, read off the public
  projection. Every field they are built from has to be in `publicApi.fields`
  already, because they end up in a public page.
- **`robots`** - `{ index, follow }`, or `null` when the content type states none.
- **`isFallback`** - whether the body you were handed is the default locale
  standing in for a missing translation.

## Automatic SEO capabilities

- **308 permanent redirects** - renaming a slug preserves the historical URL, so
  the rank a page earned follows it.
- **Canonical URLs** - built from your origin plus `canonicalPath`.
- **Hreflang** - `<link rel="alternate" hreflang="...">` for every published
  translation, with an optional `x-default`.
- **XML sitemaps** - `GET .../delivery/sitemap` returns entries plus a
  `nextCursor`; `contentSitemapXml` and `contentSitemapIndexXml` from
  `@vitnode/core/content` turn a page of entries into the XML a crawler wants.

<Callout type="info" title="Caching">
  Delivery answers have their own tags - `contentDeliveryTag`,
  `contentDeliveryRedirectTag`, `contentDeliverySitemapTag`. A background
  mutation posts the ones it invalidated to your configured origins; see
  [Cache](/docs/dev/cache).
</Callout>
