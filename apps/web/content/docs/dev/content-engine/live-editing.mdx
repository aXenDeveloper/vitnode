Live editing lets a whole team work on the same record at the same time without stepping on each other. Every editorial content type gets it automatically in the AdminCP:

- **Autosave.** Changes are saved to a shared draft a moment after you stop typing. Nothing reaches the published record until someone presses **Save** or **Publish**.
- **Presence.** Avatars show who has the record open, which field they are in and which language they are editing.
- **Field locks.** A plain field, such as a title, slug or category, is edited by one person at a time. Everyone else sees it read-only, with the editor's name, and gets the new value live.
- **Co-editing.** A [rich text](/docs/dev/content-engine/rich-text) field is the exception: several people type in it at once and see each other's cursors.

## Turn it on

Live editing needs an [editorial content type](/docs/dev/content-engine/publication-and-editorial). There is nothing else to configure:

```ts title="plugins/blog/src/content/post.ts"
export const blogPostContentType = defineContentType({
  id: "blog.post",
  tableName: "blog_posts",
  editorial: { enabled: true }, // [!code highlight]
  fields: {
    title: field.text({ localized: true, required: true }),
    content: field.richText({ localized: true, required: true }),
  },
});
```

Open an existing record in the AdminCP and you are in a live session. A form that creates a new record is not live yet, because there is no record to share.

Everyone in the session needs the content type's `can_edit` permission. Viewing a record without it does not join the session.

## What editors see

### Autosave and the shared draft

About 1.5 seconds after you stop typing, your changes are saved to the record's draft. The form header shows the state: **Saving…**, **Draft saved at 14:32**, or **Unsaved changes** when the draft differs from the published record.

There is one draft per record and language, shared by the whole team. It is the team's working copy: when you open the record, you see the draft, not only what was last saved. **Save** commits everything in the draft through the usual [versioned save](/docs/dev/content-engine/publication-and-editorial#safe-concurrent-edits), creating one revision. Autosave never creates revisions, never emits content events and never touches search or caches.

### Field locks

Clicking into a plain field takes a lock on that field, in that language. The lock lasts 60 seconds and is renewed every 20 seconds while you stay in the field. Leaving the field gives it back.

While Anna holds the title, everyone else sees the title read-only with **Anna is editing**, and the value updates live as she types. When she moves on, the field becomes editable again.

A lock that is not renewed, because a laptop went to sleep or a tab crashed, expires on its own after 60 seconds.

### Co-editing rich text

Rich text fields are not locked. Everyone in the same field and language types into one shared document, and each person's cursor and selection show with their name and color. Undo only undoes your own changes.

The shared document is saved on the server about two seconds after the last change, so it is autosaved too. **Save** writes its current content to the record as JSON.

### Resets

Restoring a revision or deleting the record throws the drafts, locks and shared documents away. Everyone in the session gets a notice and their form reloads with the new state.

## Deployment requirements

Presence and co-editing travel over the [WebSocket](/docs/dev/websocket) at `/api/ws`, so they need a long-lived Node server, such as the separate `apps/api` server or a [self-hosted](/docs/dev/deployments/self-hosted) install.

| Deployment | Autosave and locks | Presence | Rich text |
| --- | --- | --- | --- |
| Long-lived Node server | Live | Yes | Co-edited |
| Serverless, such as [Vercel](/docs/dev/deployments/cloud/vercel) | Checked every 10 seconds | No | One editor at a time, locked like a plain field |

With more than one API instance, set `REDIS_URL`. Instances share presence and shared-document updates over Redis pub/sub; without it, editors connected to different instances do not see each other.

## Where the data lives

| Table | Holds |
| --- | --- |
| `core_content_drafts` | The shared draft of plain fields, one row per record and language |
| `core_content_field_locks` | Active field locks, with their holder and expiry |
| `core_content_documents` | The Yjs state of each rich text field, per record and language |

The daily `content-editorial-cleanup` cron removes expired locks, and drafts and documents nobody touched for 30 days. A stale draft whose record has not changed since is kept, because it is somebody's unsaved work.

## HTTP API

The AdminCP calls these routes for you. They are mounted under the content type's admin module, for example `/api/@vitnode/blog/admin/content/posts`, and all of them need `can_edit`.

| Method and path | Body | Result |
| --- | --- | --- |
| `GET /{id}/locks` | | `{ locks }`: unexpired locks of the record |
| `POST /{id}/locks` | `{ field, locale, action }` with `action` `acquire`, `renew` or `release` | `{ lock }`, or `409` `CONTENT_FIELD_LOCKED` with the current holder |
| `GET /{id}/draft` | | `{ shared, translations }`: the shared draft and one draft per language |
| `PUT /{id}/draft` | `{ locale, values }` | `{ updatedAt }`, or `409` `CONTENT_FIELD_NOT_LOCKED` for fields you do not hold |

`locale` is `null` for a field that is not localized and the language code otherwise. A draft write only accepts fields you currently hold a lock on, and validates each value with the field's own rules.

## Use live state in a custom form layout

A plugin that replaces the edit form [with its own layout](/docs/dev/content-engine/admincp) can read the session from `@vitnode/core/content/admin-form`:

```tsx title="plugins/blog/src/views/admin/article/editor/header.tsx"
import {
  ContentLiveStatus,
  useContentLive,
} from "@vitnode/core/content/admin-form";

export const ArticleHeader = () => {
  const live = useContentLive();

  return (
    <header className="flex items-center justify-between gap-4">
      <ContentLiveStatus />
      {live ? <span>{live.session.members.length}</span> : null}
    </header>
  );
};
```

`useContentLive()` returns `null` outside a live form, so the same layout works for the create form.
