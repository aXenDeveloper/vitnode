When you instantiate a content model with `createContentModel`, Content Engine builds a fully typed service, Zod validation schemas, staff permissions, and event emissions.

## Prerequisites & Context

This guide assumes you have compiled your content definition into a server model using `createContentModel` in `src/database/articles.ts`:

```ts title="src/database/articles.ts"
import { createContentModel } from "@vitnode/core/content/server";
import { articleContentType } from "@/content/article";

// articleContent is the compiled model instance
export const articleContent = createContentModel(articleContentType);
```

- **`articleContent.service(c)`**: Returns a self-validating service scoped to the current Hono request context `c`, executing queries with database connection and user credentials.
- **`articleContent.schemas`**: An object containing pre-built Zod schemas (`create`, `update`, `select`, `filter`, `order`).

---

## Step-by-Step API & Service Usage

<Steps>

<Step>
### Step 1: Query Records with Service Methods

Access the service via `articleContent.service(c)` inside custom Hono route handlers:

```ts title="src/api/routes/articles.route.ts"
import { Hono } from "hono";
import { articleContent } from "@/database/articles";

const app = new Hono();

app.get("/custom-articles", async (c) => {
  const service = articleContent.service(c);

  // Query paginated list with sorting and filtering
  const { data, total } = await service.findMany({
    page: 1,
    limit: 10,
    sort: { column: "createdAt", order: "desc" },
    filter: { status: "published" },
  });

  return c.json({ data, total });
});
```
</Step>

<Step>
### Step 2: Use Generated Zod Schemas

Validate request bodies using pre-compiled Zod schemas:

```ts title="src/api/routes/articles.route.ts"
app.post("/custom-articles", async (c) => {
  const schemas = articleContent.schemas; // [!code ++]
  const body = schemas.create.parse(await c.req.json()); // [!code ++]

  const newArticle = await articleContent.service(c).create(body); // [!code ++]
  return c.json(newArticle);
});
```
</Step>

<Step>
### Step 3: Listen to Typed Content Events

Register event handlers using `eventEngine.on` to react whenever content is created, updated, or deleted:

```ts title="src/hooks/on-article-created.ts"
import { eventEngine } from "@vitnode/core/events";

eventEngine.on("content.example.article.created", async (payload) => {
  console.log(`Article #${payload.id} created by user #${payload.actor.id}`);
});
```
</Step>

</Steps>

## Core Service Methods Reference

| Method | Parameters | Return Type | Description |
| :--- | :--- | :--- | :--- |
| `findById(id)` | `number` | `Promise<Item \| null>` | Find single record by primary key |
| `findMany(options)` | `{ page, limit, sort, filter }` | `Promise<{ data, total }>` | Query paginated list with sorting and filtering |
| `create(data)` | `CreateInput` | `Promise<Item>` | Insert record and emit `created` event |
| `update(id, data)` | `id, UpdateInput` | `Promise<Item>` | Update record and emit `updated` event |
| `delete(id)` | `number` | `Promise<void>` | Delete record and emit `deleted` event |

## Automatic Staff Permissions

Registering `buildContentAdminModule` automatically seeds staff permissions based on your content type ID:

- `admin_{plugin}_content_{entity}_view`
- `admin_{plugin}_content_{entity}_create`
- `admin_{plugin}_content_{entity}_edit`
- `admin_{plugin}_content_{entity}_delete`
- `admin_{plugin}_content_{entity}_publish` (if publication is enabled)
