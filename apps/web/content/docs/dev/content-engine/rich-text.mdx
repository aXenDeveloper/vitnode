`field.richText()` is the Content Engine field for formatted text: headings, lists, links, tables, task lists and panels. Editors write it in the AdminCP with the Tiptap editor. Readers get it as plain HTML rendered by `RichTextContent`, a small React component that never loads the editor, so the public page stays light. Your readers came for the article, not for an editor they will never type in.

## Define a rich text field

Add the field to a content type. A blog article body is the typical case:

```ts title="plugins/blog/src/content/post.ts"
import { defineContentType, field } from "@vitnode/core/content";

export const blogPostContentType = defineContentType({
  // id, tableName, localization, publicApi as before
  fields: {
    title: field.text({ localized: true, required: true, maxLength: 255 }),
    content: field.richText({ localized: true, required: true }), // [!code highlight]
  },
});
```

The value is a ProseMirror document, the same JSON Tiptap's `editor.getJSON()` returns:

```json
{
  "type": "doc",
  "content": [
    { "type": "paragraph", "content": [{ "type": "text", "text": "Hello!" }] }
  ]
}
```

The column is `jsonb`. Every write is validated: the shape must be a document, it can nest at most 64 levels deep, and its JSON must fit in `maxBytes` (1 MB by default). With `required: true`, a document without any text or media is refused, so an empty editor cannot be saved. All options are in [Fields](/docs/dev/content-engine/fields#rich-text).

The AdminCP form shows the editor automatically. It is loaded lazily, so forms without a rich text field never download it.

## Render it on a public page

Import `RichTextContent` from `@vitnode/core/components/rich-text` and pass the document. It works during SSR and in the browser:

```tsx title="plugins/blog/src/pages/post-page.tsx"
import { RichTextContent } from "@vitnode/core/components/rich-text";
import { zodRichTextDocument } from "@vitnode/core/content";
import { z } from "zod";

const zodBlogPost = z.object({
  content: zodRichTextDocument,
  title: z.string(),
});

const BlogPostPage = ({ item }: { item: z.infer<typeof zodBlogPost> }) => (
  <article>
    <h1>{item.title}</h1>
    <RichTextContent className="leading-relaxed" content={item.content} />
  </article>
);
```

The output is wrapped in `<div class="tiptap">` and uses the same classes as the editor (`list-disc`, `tableWrapper`, `tiptap-panel` and so on), so the existing `@vitnode/core/styles/tiptap.css` styles it.

`RichTextContent` treats the document as untrusted input:

- Links keep only `http:`, `https:`, `mailto:`, `tel:`, relative and `#` targets. A `javascript:` or `data:` link renders as plain text.
- A link that opens a new tab gets `rel="noopener noreferrer nofollow"`.
- Styles come from an allowlist: text colors, font sizes with a unit, and text alignment.
- An unknown node renders its children; an unknown mark renders plain text.

## Add or replace a renderer

Pass `nodes` or `marks` to change how one type renders. The keys are ProseMirror type names, and each renderer receives the node (or mark) and its already rendered children:

```tsx
<RichTextContent
  content={item.content}
  marks={{
    mention: ({ children, mark }) => (
      <a href={`/profile/${String(mark.attrs?.id)}`}>{children}</a>
    ),
  }}
  nodes={{
    heading: ({ children, node }) =>
      node.attrs?.level === 2 ? <h2 className="scroll-mt-20">{children}</h2> : <h3>{children}</h3>,
  }}
/>
```

A custom renderer is your code, so it skips the built-in link and style allowlists. Sanitize anything it reads from `attrs`; `sanitizeRichTextHref` from the same import does links.

## Get plain text or HTML

Three helpers work on the server and in the browser without React. Import them from `@vitnode/core/content`:

| Helper                     | Returns   | Use it for                                                                 |
| -------------------------- | --------- | -------------------------------------------------------------------------- |
| `richTextToPlainText(doc)` | `string`  | Search, excerpts, AI prompts, word counts. One line per block, no markup  |
| `richTextToHtml(doc)`      | `string`  | Emails and feeds. Escaped, with the same allowlists as `RichTextContent`   |
| `isRichTextEmpty(doc)`     | `boolean` | Checking whether a document has any text or media                          |

```ts
import { richTextToPlainText } from "@vitnode/core/content";

const words = richTextToPlainText(post.content).split(/\s+/).length;
```

The Content Engine uses them for you: the site search indexes the words of a rich text field, `delivery.seo.descriptionField` can name one and gets plain text, and the revision history compares documents as text.

## Use the editor in your own form

Outside the Content Engine, `AutoFormEditor` from `@vitnode/core/components/form/fields/editor` stores HTML by default. Add `format="json"` to store a document instead:

```tsx
<AutoFormEditor format="json" label="Body" {...props} />
```

## Check the result

Open an article in **AdminCP**, write a heading and a list, and save. The public page shows the same content, and the browser's network tab shows no `@tiptap` or `prosemirror` chunk for that page.

Several editors can work on the same rich text field at once; [Live editing](/docs/dev/content-engine/live-editing) covers co-editing and presence.
