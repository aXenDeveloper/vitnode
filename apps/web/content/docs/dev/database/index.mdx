VitNode stores data in [PostgreSQL](https://www.postgresql.org) through [Drizzle ORM](https://orm.drizzle.team). A plugin defines its tables in TypeScript, VitNode turns them into SQL migrations, and routes query them with `c.get("db")`. In this lesson the `site-notes` endpoints stop returning sample data and read a real `site_notes` table.

## Before you begin

- The `site-notes` plugin from [Plugin page](/docs/dev/plugins/page), with `pnpm dev` running at the workspace root.

<Steps>

<Step>

### Define the table

Create `src/database/notes.ts`:

```ts title="plugins/site-notes/src/database/notes.ts"
import { camelCase } from "drizzle-orm/pg-core";

export const site_notes = camelCase.table.withRLS("site_notes", t => ({
  id: t.serial().primaryKey(),
  title: t.varchar({ length: 200 }).notNull(),
  body: t.text().notNull(),
  createdAt: t.timestamp().notNull().defaultNow(),
}));
```

- **Every table is a named export of a file in `src/database/`.** The migration generator reads those exports from the plugin's build output; a table that is not exported there never reaches the database.
- **Prefix the table name with the plugin**, as `site_notes` does, so two plugins never claim the same table.
- **`camelCase.table`** keeps the TypeScript and column names identical (`createdAt`). **`withRLS`** turns on row-level security, as every core table does.

</Step>

<Step>

### Generate and apply the migration

`pnpm dev` already rebuilt the plugin when you saved. From the workspace root, create the migration and apply it:

<Tabs groupId="package-manager" persist items={["bun", "pnpm", "npm"]} label="Migrate the database">

```bash tab="bun"
bun run db:migrate
```

```bash tab="pnpm"
pnpm db:migrate
```

```bash tab="npm"
npm run db:migrate
```

</Tabs>

`db:migrate` compares your tables with the last migration, writes a new folder such as `migrations/20261024183641_little_the_phantom/` in the app that owns the database (`apps/web` in a Single App, `apps/api` in a Monorepo App), applies it and seeds core data. **Commit that folder**, because production applies the same files. Without `pnpm dev` running, run `pnpm build:plugins` first so the generator sees the new table.

</Step>

<Step>

### Add demo notes

There is no write endpoint yet, so add three notes with SQL. With the Docker database from Setup, run this from the workspace root (the `my-vitnode` folder):

```bash
docker compose -p my-vitnode-vitnode-dev exec -T database psql -U root -d vitnode -c "INSERT INTO site_notes (title, body) VALUES ('Welcome to site notes', 'Short updates for everyone on the site.'), ('Office closed on Friday', 'We are back on Monday at 9:00.'), ('New coffee machine', 'It is in the kitchen. Please descale it on Fridays.');"
```

It answers `INSERT 0 3`. `database` is the PostgreSQL service in the generated `docker-compose.yml`, and `-p my-vitnode-vitnode-dev` is the Compose project that `docker:dev` started it in. If you named your project something else, use the `-p` value from the `docker:dev` script in your root `package.json`.

The notes get the ids `1`, `2` and `3` in that order, which later lessons use. With your own PostgreSQL, run the same `INSERT` in any client connected to `POSTGRES_URL`. The [Permissions](/docs/dev/working-with-users/staff-permissions) lesson adds the endpoint that creates notes properly.

</Step>

<Step>

### Read the table in the list route

Replace the handler of `src/api/modules/notes/list.route.ts`, and its imports. Select only the columns the response schema declares:

```ts title="plugins/site-notes/src/api/modules/notes/list.route.ts"
import { z } from "@hono/zod-openapi";
import { desc } from "drizzle-orm"; // [!code ++]

import { buildRoute } from "@/api/builders";
import { site_notes } from "@/database/notes"; // [!code ++]

import { zodNote } from "./notes.schema";
import { sampleNotes } from "./sample-notes"; // [!code --]

export const listNotesRoute = buildRoute({
  route: {
    method: "get",
    path: "/",
    responses: {
      200: {
        content: { "application/json": { schema: z.array(zodNote) } },
        description: "Every note, newest first.",
      },
    },
  },
  handler: c => c.json(sampleNotes, 200), // [!code --]
  // [!code ++:8]
  handler: async c => {
    const notes = await c
      .get("db")
      .select({ id: site_notes.id, title: site_notes.title, body: site_notes.body })
      .from(site_notes)
      .orderBy(desc(site_notes.createdAt), desc(site_notes.id));

    return c.json(notes, 200);
  },
});
```

</Step>

<Step>

### Read the table in the detail route

Replace the handler of `src/api/modules/notes/show.route.ts` the same way. The params and responses stay as they are:

```ts title="plugins/site-notes/src/api/modules/notes/show.route.ts"
import { eq } from "drizzle-orm"; // [!code ++]

import { site_notes } from "@/database/notes"; // [!code ++]
import { sampleNotes } from "./sample-notes"; // [!code --]

  // [!code ++:11]
  handler: async c => {
    const { id } = c.req.valid("param");
    const [note] = await c
      .get("db")
      .select({ id: site_notes.id, title: site_notes.title, body: site_notes.body })
      .from(site_notes)
      .where(eq(site_notes.id, id));
    if (!note) return c.body(null, 404);

    return c.json(note, 200);
  },
```

Then delete `src/api/modules/notes/sample-notes.ts`; nothing imports it any more.

</Step>

</Steps>

## Check the result

```bash
curl http://localhost:3000/api/site-notes/notes
```

The list now starts with **New coffee machine**, the newest note, and `GET /api/site-notes/notes/2` returns **Office closed on Friday**. Reload `http://localhost:3000/site-notes/notes` and the page shows all three notes, with no change to its code. Run the `INSERT` again with another title and it appears on the next reload.
