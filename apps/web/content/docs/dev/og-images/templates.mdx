A template is a function that turns the card's data into JSX. Write it in its own `.tsx` file, register it in `ogImages.templates`, and every place that renders an image can pick it by id. The AdminCP [preview page](/docs/dev/og-images/admincp-preview) lists it straight away.

<Steps>
<Step>

### Write the template

Create a `.tsx` file next to your API config. It receives an `OgImageTemplateInput` and returns JSX with inline `style` objects:

```tsx title="src/og/minimal-template.tsx"
import type { OgImageTemplateInput } from "@vitnode/core/og-image/server";

import { truncateOgText } from "@vitnode/core/og-image/server";

export const minimalOgImageTemplate = ({
  height,
  locale,
  siteName,
  theme,
  title,
  width,
}: OgImageTemplateInput) => (
  <div
    lang={locale}
    style={{
      alignItems: "center",
      backgroundColor: "#ffffff",
      color: "#0f172a",
      display: "flex",
      flexDirection: "column",
      fontFamily: theme.fontFamily,
      gap: 32,
      height,
      justifyContent: "center",
      padding: 96,
      width,
    }}
  >
    <div style={{ display: "block", fontSize: 72, fontWeight: 700, lineClamp: 3, textAlign: "center" }}>
      {truncateOgText(title, 90)}
    </div>
    <div style={{ color: theme.accentColor, display: "flex", fontSize: 32 }}>
      {siteName}
    </div>
  </div>
);
```

`truncateOgText` cuts text at a word boundary and adds `…`, so the same title always wraps the same way.

</Step>
<Step>

### Register it

Import the file in `vitnode.api.config.ts`. Setting `templates` replaces the default list, so add the built-in template too if you still want it:

```ts title="src/vitnode.api.config.ts"
import { defaultOgImageTemplateEntry } from "@vitnode/core/og-image/server";

import { minimalOgImageTemplate } from "./og/minimal-template";

ogImages: {
  defaultTemplate: "default",
  templates: {
    default: defaultOgImageTemplateEntry,
    minimal: { label: "Minimal", render: minimalOgImageTemplate, version: "1" },
  },
},
```

`version` is part of every cached image's key. Bump it whenever you change the template's output, and old cards are rendered again on their next request. `label` is the name shown in the AdminCP.

</Step>
<Step>

### Use it

A content type picks it with `delivery.seo.openGraph.image.template: "minimal"`, and your own route with `ogImageResponse(c, { template: "minimal", ... })`. Leave it out to use `defaultTemplate`.

</Step>
</Steps>

## What a template receives

| Field         | Type                           | Notes                                                                            |
| ------------- | ------------------------------ | -------------------------------------------------------------------------------- |
| `title`       | `string`                       | Plain text, trimmed, never empty                                                 |
| `description` | `string \| null`               | Plain text                                                                       |
| `siteName`    | `string`                       | `branding.siteName` or the API's `metadata` title                                |
| `logo`        | `OgImageTemplateAsset \| null` | `{ src, width, height, alt }`, `src` is always a `data:` URI                     |
| `cover`       | `OgImageTemplateAsset \| null` | The page's cover, resized to fit the card                                        |
| `locale`      | `string`                       | The language the content was actually served in, after any fallback              |
| `url`         | `string \| null`               | The page's canonical URL, when the caller knows it                               |
| `theme`       | `OgImageTheme`                 | Colors and `fontFamily` from `ogImages.theme`                                    |
| `width`, `height` | `number`                   | Always `1200` and `630`                                                          |

## Styling rules

`@vercel/og` renders with [Satori](https://github.com/vercel/satori), which supports a subset of CSS:

- Use inline `style` objects. `className`, Tailwind classes and CSS files do nothing.
- Layout is flexbox only. A `<div>` with more than one child needs `display: "flex"`; there is no grid.
- Don't render app components or use hooks. A template runs on the server once per image, outside React's tree.
- Use `<img>` only with the `src` values from the input, which are already `data:` URIs. A remote URL would be fetched by the renderer without VitNode's size and address checks.
- `lineClamp` works on an element with `display: "block"`.

## Use your own fonts

The bundled fonts are Inter regular and bold in two subsets, `Inter` (Latin) and `Inter Latin Ext` (Polish, Czech, Turkish and other European Latin letters). To use another font, list its files and set the font stack:

```ts title="src/vitnode.api.config.ts"
import { readFile } from "node:fs/promises";

ogImages: {
  fonts: [
    { name: "Lora", weight: 400, data: async () => await readFile("./fonts/Lora-Regular.ttf") },
    { name: "Lora", weight: 700, data: async () => await readFile("./fonts/Lora-Bold.ttf") },
  ],
  theme: { fontFamily: "Lora" },
},
```

- TTF, OTF and WOFF work. WOFF2 and variable fonts do not.
- Each font is loaded once per process, on the first render.
- Satori uses one file per name and weight. When a font is split into subsets, give each subset its own `name` and list them all in `fontFamily`, like the bundled `"Inter, 'Inter Latin Ext'"`.
- Characters no font covers, such as emoji or Chinese, are fetched from a CDN by `@vercel/og` at render time. Ship a font for every script your titles use if the server has no outbound network.
- Bump `ogImages.version` after replacing a font file under the same name.
