A plugin is the starting point for a VitNode feature. It keeps routes, API
modules, data, translations, and AdminCP extensions together in one installable
package. Nice boundaries; fewer archaeological digs later.

<Callout type="warn" title="Plugins need a workspace">
  Run the generator from a repository with `turbo.json`. When creating an app,
  turn on Turborepo first; a plain single-folder app has nowhere for
  `plugins/*`.
</Callout>

<Steps>
  <Step>

### Generate the package

Run this at the workspace root and enter a package name such as
`@acme/site-notes` when prompted:

<Tabs groupId="package-manager" persist items={["bun", "pnpm", "npm"]} label="Create a VitNode plugin">

```bash tab="bun"
bun create vitnode-app@canary --plugin
```

```bash tab="pnpm"
pnpm create vitnode-app@canary --plugin
```

```bash tab="npm"
npm create vitnode-app@canary -- --plugin
```

</Tabs>

  </Step>
  <Step>

### Run/Restart it and visit the route

<Tabs groupId="package-manager" persist items={["bun", "pnpm", "npm"]} label="Start the plugin in development">

```bash tab="bun"
bun dev
```

```bash tab="pnpm"
pnpm dev
```

```bash tab="npm"
npm run dev
```

</Tabs>

  </Step>
  <Step>

### Check the generated page

Visit the route printed in the console, such as `http://localhost:3000/site-notes`. You should see a page with a title and a link to the plugin's README.
