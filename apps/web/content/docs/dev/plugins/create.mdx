A plugin is the starting point for a VitNode feature. It keeps routes, API
modules, data, translations, and AdminCP extensions together in one installable
package. Nice boundaries; fewer archaeological digs later.

<Callout type="warn" title="Plugins need a workspace">
  Run the generator from a repository with `turbo.json`. When creating an app,
  turn on Turborepo first; a plain single-folder app has nowhere for
  `plugins/*`.
</Callout>

<Steps>
  <Step>

### Generate the package

Run this at the workspace root and enter a package name such as
`@acme/site-notes` when prompted:

<Tabs groupId="package-manager" persist items={["bun", "pnpm", "npm"]} label="Create a VitNode plugin">

```bash tab="bun"
bun create vitnode-app@canary --plugin
```

```bash tab="pnpm"
pnpm create vitnode-app@canary --plugin
```

```bash tab="npm"
npm create vitnode-app@canary -- --plugin
```

</Tabs>

  </Step>
  <Step>

### Run/Restart it and visit the route

<Tabs groupId="package-manager" persist items={["bun", "pnpm", "npm"]} label="Start the plugin in development">

```bash tab="bun"
bun dev
```

```bash tab="pnpm"
pnpm dev
```

```bash tab="npm"
npm run dev
```

</Tabs>

  </Step>
  <Step>

### Check the generated page

Visit the route printed in the console, such as `http://localhost:3000/site-notes`. You should see a page with a title and a link to the plugin's README.

## What gets generated

<Files>
  <Folder name="plugins" defaultOpen>
    <Folder name="site-notes" defaultOpen>
      <Folder name="src" defaultOpen>
        <Folder name="api/modules/hello">
          <File name="hello.module.ts" />
          <File name="hello.module.test.ts" />
          <File name="hello.route.ts" />
        </Folder>
        <Folder name="locales">
          <File name="en.json" />
          <File name="index.ts" />
        </Folder>
        <Folder name="pages">
          <File name="home-page.tsx" />
        </Folder>
        <File name="config.api.ts" />
        <File name="config.tsx" />
        <File name="const.ts" />
        <File name="routes.ts" />
      </Folder>
      <File name="package.json" />
      <File name="README.md" />
      <File name="vitest.config.ts" />
    </Folder>
  </Folder>
</Files>

One page at `/site-notes` whose loader calls the plugin's own `hello` endpoint, its strings, and a Vitest test for the endpoint (`pnpm test` in the plugin). The generator also registers the plugin in your apps' `vitnode.config.ts` and `vitnode.api.config.ts`, installs it and builds it.

The plugin name must be a valid npm name and must not be one of core's routes: `admin`, `api`, `core`, `discover`, `files`, `login`, `notifications`, `register`, `search`, `users` or `vitnode`.

Check the result the way your app will load it:

```bash
vitnode plugin validate site-notes
```

See [Plugin CLI](/docs/dev/cli/plugins) for what validation checks.
