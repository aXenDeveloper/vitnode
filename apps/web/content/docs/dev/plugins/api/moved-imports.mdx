---
title: Moved API imports
description: Where the VitNode API files moved when routes got one file each under routes/, and how the former deep import paths keep working until you update them.
icon: ArrowRightLeft
---

VitNode keeps one endpoint per file in each module's `routes/` folder, names modules `<feature>.module.ts`, and puts schemas next to their module. To get there, some API files moved or were split. Their endpoints did not change: the methods, paths, permissions and `fetcher` calls are the same. If your code imports one of the paths below, it keeps working, but the import is deprecated. Switch to the new path before the compatibility entries are removed in a future major release.

## How the old paths still resolve

- **Moved as a whole:** the package's `exports` map the old path straight to the new file, so every export is still there.
- **Split or trimmed:** the old path points at a small compatibility module under `dist/src/compat/`. It re-exports each former export from its new module, marked `@deprecated`, and contains no code of its own. It pulls in no route code the old file did not already contain, so a browser-safe schema import stays browser-safe.
- **Still at the same path:** a file that only lost some exports, such as `@vitnode/core/api/modules/ai/routes/stream.route`, still serves its remaining exports. Only the moved ones are deprecated.

Nothing was removed without a replacement, so no import from the paths below breaks. In the tables, "everything else: unchanged" marks those remaining exports.
