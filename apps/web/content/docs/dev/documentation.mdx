Documentation lives in `apps/web/content/docs`. Aim for a page that answers one
question quickly, with a real example and just enough personality to keep the
reader awake. Tiny joke, big clarity.

## Start with searchable frontmatter

Every page needs a specific title, a 50–170 character description, and a Lucide
icon. Fumadocs renders the page title, so do not add another `#` heading.

```mdx title="apps/web/content/docs/dev/example.mdx"
---
title: Add a Plugin Route
description: Add a reusable plugin route with a short TanStack Start page and searchable metadata.
icon: Route
---
```

## Show changes, not a wall of code

Use code-diff annotations where the reader should edit a line:

```ts title="plugins/notes/src/routes/manifest.ts"
export const routes = [
  // [!code ++:5]
  {
    entry: 'routes/notes-page',
    id: 'notes',
    path: '/notes',
  },
]
```

Use `<Steps>`, `<Callout>`, and `<Cards>` for a tutorial’s path, warning, and
next choice. Add `icon={<SomeIcon />}` to Cards so scanning the docs feels a
little less like reading a tax return.

## Always show all package managers

Any command mentioning Bun, pnpm, or npm needs this tab pattern:

<Tabs groupId="package-manager" persist items={["bun", "pnpm", "npm"]} label="Run the example">

```bash tab="bun"
bun dev
```

```bash tab="pnpm"
pnpm dev
```

```bash tab="npm"
npm run dev
```

</Tabs>

Use a short image prompt comment near a flow that would benefit from a screen,

## Finish with a fast check

<Tabs groupId="package-manager" persist items={["bun", "pnpm", "npm"]} label="Check documentation">

```bash tab="bun"
bun run docs:check
```

```bash tab="pnpm"
pnpm docs:check
```

```bash tab="npm"
npm run docs:check
```

</Tabs>

The check catches missing frontmatter, weak search descriptions, incomplete
category metadata, and one-manager command examples before they sneak into a PR.
