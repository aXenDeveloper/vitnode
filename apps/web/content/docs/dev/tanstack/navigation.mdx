title: Navigation
description: Link between pages, and let the router handle the language.
---

Inside the app, use TanStack Router's `Link`. It builds the href, applies the
locale prefix, and preloads the destination on hover.

## Example

```tsx
import { Link } from "@tanstack/react-router";

<Link to="/discover">Discover</Link>;
```

That renders `/discover` for an English reader and `/pl/discover` for a Polish
one. Same component, same `to`, no branch.

## The locale is not yours to write

`/discover` and `/pl/discover` are **one route**. The prefix is stripped before
the router matches, and written back into every href the router builds:

```txt
browser   /pl/discover   -->  /discover     the route tree
<Link to="/discover">    -->  /pl/discover  the rendered href
```

So a hand-built `` `/${locale}/discover` `` produces `/pl/pl/discover`, and a
`to="/pl/discover"` names a route that does not exist. Write the logical path and
let the router do the rest.

<Callout type="info" title="`/admin` and `/api` carry no prefix">
  Both are outside the localized URL space, so nothing is stripped or added
  there. The AdminCP takes its language from the operator's stored preference.
</Callout>

## Plugin route modules

A plugin page must not import a router - that is what keeps one plugin
installable into any VitNode host - and **VitNode does not currently expose a
router-neutral `Link` for plugin modules**. That is a real gap rather than an
omission you can work around.

What works today:

- Render text instead of a link where you can. A plugin breadcrumb is a label for
  exactly this reason.
- Accept a link component as a prop from whatever renders your component, which
  is how core's own shared views do it (`LinkComponent`).
- Use a plain `<a href>` only for an **external** destination. An internal one
  will do a full page load and will lose the locale prefix.

## When to use it

- **`<Link>`** for anything inside this app.
- **`<a href>`** for another origin - GitHub, a status page, a provider's docs.
- **`useNavigate()`** when the destination is decided in code rather than by a
  click, such as after a form submits.
