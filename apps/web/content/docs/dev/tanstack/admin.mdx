---
title: AdminCP routes
description: Put a plugin page inside the admin panel with one field.
---

An AdminCP page is an ordinary plugin route with `area: "admin"`. That one field
frames it with the sidebar, the breadcrumb area, the command palette and the
admin session guard.

## Example

```ts title="plugins/my-plugin/src/routes/manifest.ts"
{
  area: "admin",
  entry: "routes/admin-settings",
  id: "settings",
  path: "/admin/my-plugin",
  namespaces: ["my-plugin.admin.settings"],
}
```

```tsx title="plugins/my-plugin/src/routes/admin-settings.tsx"
import { useTranslations } from "use-intl";

const AdminSettingsPage = () => {
  const t = useTranslations("my-plugin.admin.settings");

  return (
    <div className="flex flex-col gap-4 p-4">
      <h1 className="text-2xl font-semibold tracking-tight">{t("title")}</h1>
    </div>
  );
};

export default AdminSettingsPage;
```

`@vitnode/example` ships exactly this at `/admin/example` - it is the smallest
working one in the repository.

## The rules

- **Write the full `/admin/…` path.** `area` chooses a shell, never a prefix.
  Both shells are pathless, so nothing is added to your URL.
- **Do not add `requires: "authenticated"`.** That field is about the *public*
  session; the AdminCP runs on its own session under its own cookie, and the
  shell's guard already runs before your page's chunk is fetched. The manifest
  rejects it rather than ignoring it.
- **Render no `<main>`.** The admin shell's content area already is the
  document's one `main` landmark.
- **Hono is still the boundary.** The guard decides whether to *show* a page. Every
  route and action behind it must check the staff permission itself, or an
  administrator without it gets the data by calling the API directly.

## Gating what the page shows

Wrap privileged sections so the UI matches what the API will allow:

```tsx
import { AdminStaffPermissionGate } from "@vitnode/core/components/staff-permission/provider";

<AdminStaffPermissionGate
  module="settings"
  permission="can_edit"
  plugin="my-plugin"
>
  <SaveButton />
</AdminStaffPermissionGate>;
```

The gate is presentation. The refusal that matters is the one your Hono route
returns.

## Adding it to the sidebar

The sidebar is a separate list from the route manifest, declared in your plugin's
`admin/nav` module so an app can render the navigation without loading your
screens. See [AdminCP Pages](/docs/dev/plugins/admin-page#navigation-items).
