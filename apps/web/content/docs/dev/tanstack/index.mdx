VitNode's web application is a [TanStack Start](https://tanstack.com/start) app.
Pages are TanStack Router routes, cached data is TanStack Query, and every read
or write of real data goes to the Hono API - the same API `apps/api` serves on
its own.

## The one boundary worth memorising

```txt
TanStack Start  ->  pages, routing, rendering
Hono            ->  the API, and every security decision
```

A route decides what a visitor *sees*. Hono decides what they are *allowed to
see*, from the session cookie, on the server, on every request. A route guard is
navigation - it saves someone a wasted page load - and it is never the thing
protecting your data.

## The shape of an app

```txt
apps/web/
├── src/
│   ├── routes/            one file per URL this app owns
│   ├── site/              the pages those routes render
│   ├── lib/               page-head, i18n, auth wiring
│   └── vitnode.config.ts  which plugins are installed
└── vite.config.ts
```

And the shape of a plugin, which is where most VitNode features actually live:

```txt
plugins/my-plugin/
└── src/
    ├── config.tsx         registers the plugin
    ├── locales/           its translations
    └── routes/
        ├── manifest.ts    the URLs it claims
        └── home-page.tsx  what one of them renders
```

Nothing is copied. The app reads the manifest at build time, generates a lazy
`import()` for each entry, and the bundler gives every page its own chunk.

## Plugins are framework-neutral

A plugin route module imports `@vitnode/core/routing` - which is data and types,
with no framework in it - and `use-intl`. It imports no router. That is what lets
one plugin serve any VitNode host, and it is a permanent property of the plugin
contract rather than a phase.
