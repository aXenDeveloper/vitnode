---
title: Create your first plugin
description: Scaffold a plugin, register it, and open the page it serves.
---

A plugin is a package with a route manifest. The generator writes one for you,
already wired.

## Example

import { Tab, Tabs } from "fumadocs-ui/components/tabs";

<Tabs groupId='package-manager' persist items={['bun', 'pnpm', 'npm']} label='Create a plugin'>

```bash tab="bun"
bun create vitnode-app@canary --plugin
```

```bash tab="pnpm"
pnpm create vitnode-app@canary --plugin
```

```bash tab="npm"
npx create-vitnode-app@canary --plugin
```

</Tabs>

Run it from the root of your monorepo. It asks for a name and writes:

```txt
plugins/my-plugin/
└── src/
    ├── config.tsx           registers the plugin
    ├── locales/
    │   ├── en.json          the strings the page renders
    │   └── index.ts         the barrel config.tsx registers
    └── routes/
        ├── manifest.ts      declares one route at /my-plugin
        └── home-page.tsx    what it renders
```

Then register it in your app:

```ts title="src/vitnode.config.ts"
import { buildConfig } from "@vitnode/core/vitnode.config";
import { myPlugin } from "my-plugin/config"; // [!code highlight]

export const vitNodeConfig = buildConfig({
  // ...
  plugins: [myPlugin()], // [!code highlight]
});
```

Start the app and open `/my-plugin`.

## What just happened

`config.tsx` handed VitNode two things: the plugin's translations, and the array
from `routes/manifest.ts`. The build read that array, generated one lazy
`import()` per entry, and mounted each one on the app's route tree under the
site shell.

Your page was never copied into the application. It stays in your package, in its
own chunk, and it reaches the browser from there - so there is no generated file
to edit and nothing in `apps/*` to keep in sync.

## When to use one

- **Anything that ships as a feature.** Pages, an API, database tables, admin
  screens, translations - a plugin can hold all of them.
- **Anything you want installable elsewhere.** A plugin is a package; the app
  that installs it lists one line.
- **Not for a page that is only ever this site's own.** A marketing page belongs
  in the app's own `src/routes`, not in a package.

<Callout type="info" title="A plugin is more than routes">
  The scaffold gives you the routing path only. API modules, database tables,
  content types, events and AdminCP screens each have their own guide - start
  from [Plugins](/docs/dev/plugins/create) when you need one.
</Callout>
