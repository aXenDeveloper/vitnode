Register offers with `buildModule({ paymentOffers: [...] })` on any module of
your plugin's API.

### Snapshots

`PaymentPurchaseSnapshot` - `id` (public UUID), `userId`, `pluginId`,
`offerId`, `offerName`, `interval`, `amount`, `currency`, `paidAt`,
`fulfillmentStatus`, `refundedAmount`, `refundStatus` (`none | partial | full`).

`PaymentSubscriptionSnapshot` - `id`, `purchaseId`, `userId`, `pluginId`,
`offerId`, `interval`, `amount`, `currency`, `status`, `paidThrough`,
`cancelAtPeriodEnd`, `endedAt`.

## The provider contract

A provider is a plain object. Optional parts are capabilities: a provider
without `subscriptions` cannot sell plans, and core refuses rather than
returning partial results.

```ts
interface PaymentProvider {
  id: string // "stripe"
  name: string // "Stripe"
  scope: string // "test" | "live" - stored next to every provider id
  currencies: readonly string[]
  checkAmount?: (money: Money) => string | null
  customers: { create(input, { idempotencyKey }): Promise<{ customerId: string }> }
  checkout: {
    create(input: ProviderCheckoutInput, { idempotencyKey }): Promise<ProviderCheckout>
    retrieve(checkoutId: string): Promise<ProviderCheckout>
    expire(checkoutId: string): Promise<ProviderCheckout>
  }
  payments: { retrieve(paymentId: string): Promise<ProviderPayment> }
  subscriptions?: {
    retrieve(subscriptionId: string): Promise<ProviderSubscription>
    retrieveInvoice(invoiceId: string): Promise<ProviderInvoice>
  }
  portal?: {
    createSession(input: { customerId; returnUrl; locale? }): Promise<{ url: string }>
  }
  webhooks: {
    verify(input: { body: Uint8Array; headers: Headers }): Promise<ProviderWebhookEvent>
  }
}
```

`providerCapabilities(provider)` returns `{ oneTimePayments, subscriptions,
customerPortal, currencies, intervals }` - the shape the public settings expose.

### Normalized results

| Type                   | Key fields                                                                                                   |
| ---------------------- | ------------------------------------------------------------------------------------------------------------ |
| `ProviderCheckout`     | `id`, `status` (`open, complete, expired`), `paymentStatus` (`paid, unpaid, failed, no_payment_required`), `reference`, `paymentId`, `subscriptionId`, `amountTotal`, `currency`, `url` |
| `ProviderSubscription` | `id`, `status`, `providerStatus`, `currentPeriodEnd`, `cancelAtPeriodEnd`, `cancelAt`, `endedAt`, `amount`, `currency`, `interval`, `priceId`, `latestInvoiceId`, `reference` |
| `ProviderInvoice`      | `id`, `subscriptionId`, `status` (`open, paid, void, uncollectible`), `amountPaid`, `periodStart`, `periodEnd`, `paidAt`, `paymentId` |
| `ProviderPayment`      | `id`, `amount`, `amountRefunded` (succeeded refunds only), `currency`, `refunds[]`, `disputes[]`               |
| `ProviderWebhookEvent` | `id`, `type`, `scope`, `target` - `{ kind, id }` with kind `checkout`, `subscription`, `payment` or `invoice` (plus a `signal`), or `null` to ignore |

All amounts are ISO minor units. A provider that counts a currency differently
converts inside its adapter.

### Errors

| Error                          | Meaning                                                                                       |
| ------------------------------ | --------------------------------------------------------------------------------------------- |
| `PaymentProviderError`         | `kind`: `uncertain` (no answer - may have happened), `unavailable` (retry later), `rejected`, `not_found` |
| `PaymentWebhookSignatureError` | The request is not provably from the provider - answered with `400`                           |
| `PaymentsConfigError`          | Explicit configuration is wrong - thrown at startup                                           |

`uncertain` and `unavailable` are retried; the others are recorded as permanent
failures for the AdminCP.

## Money helpers

```ts
import { assertMinorUnits, formatMoney, toDecimalString } from '@vitnode/core/payments'

formatMoney({ amount: 1900, currency: 'PLN' }, { locale: 'pl-PL', currencyDisplay: 'code' }) // "19,00 PLN"
formatMoney({ amount: 1900, currency: 'USD' }, { locale: 'en-US', currencyDisplay: 'symbol' }) // "$19.00"
formatMoney({ amount: 1900, currency: 'JPY' }, { locale: 'en-US' }) // "¥1,900"
toDecimalString({ amount: 1900, currency: 'PLN' }) // "19.00"
assertMinorUnits(19.99) // throws - money is never a float
```

In React, `useMoneyFormatter()` from `@vitnode/core/tanstack/payments` binds
`formatMoney` to the reader's locale and the install's display settings.

## HTTP API

| Route                                                  | Who         | Purpose                                           |
| ------------------------------------------------------ | ----------- | ------------------------------------------------- |
| `GET /payments/settings`                               | anyone      | Public settings projection                        |
| `GET /payments/offers?pluginId=`                       | anyone      | A plugin's offers with purchasable prices         |
| `POST /payments/checkout`                              | signed in   | Start or resume a checkout                        |
| `GET /payments/purchases`, `/purchases/{id}?refresh=`  | owner       | Billing history, one purchase (optionally re-checked) |
| `POST /payments/purchases/{id}/cancel`                 | owner       | Cancel an unfinished checkout                     |
| `GET /payments/subscriptions`                          | owner       | The user's subscriptions                          |
| `POST /payments/portal`                                | signed in   | Customer Portal session for the user's own customer |
| `POST /payments/webhooks/{providerId}`                 | provider    | Signed webhooks                                   |
| `/admin/payments/*`                                    | staff       | Overview, lists, detail, retries (`payments: can_view`, `can_retry`) |

All paths are under `/api/@vitnode/core`. Owner routes answer `404` for
records that belong to someone else and send `Cache-Control: private, no-store`.
