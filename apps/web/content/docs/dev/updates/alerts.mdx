You do not have to open **System → Plugins** to notice an update. VitNode shows the results of the [update checks](/docs/dev/updates/admin) in three more places across the AdminCP: a count in the navigation, a security alert in the header and a dashboard widget. All three read the results already stored by the last check. Opening them never contacts a publisher and never starts a check.

## Who sees the alerts

Staff with **Plugins → View installed plugins and their versions** (`plugins.can_view`) see all three. Everyone else sees none of them, and their browser never asks for the data. Running a check still needs `plugins.can_check_updates` and stays a button on the Plugins page.

## The count next to System → Plugins

A number next to **System → Plugins** tells you how many packages have a newer release on their channel. Core counts as one package and every plugin counts once, even when its API and web app are registered separately. It is the same number of _Update available_ rows the Plugins page shows.

- The count only appears when it is above zero. While the data loads, or if it cannot be loaded, the menu looks exactly as before.
- Security updates do not add to the count. They have their own alert in the header.
- When the **System** group is folded, the count moves to the **System** item. In the collapsed icon sidebar a small dot marks the icon, and the count sits next to **Plugins** in the menu that opens.

## The security alert in the header

When a security update affects something you run, a red pill appears in the AdminCP header, next to search, on every page:

> **2 security updates**

On a phone it shrinks to the shield and the number. Each component counts once, however many security updates match it. The pill has no close button on purpose: it disappears on its own once no evaluated finding applies to what you run - after you upgrade and redeploy, or after a check finds the publisher changed the affected range. It sits in the header, so it never pushes the page down.

Click it to see what is waiting, in two groups:

- **Security fixes** - every package a security update affects, with the version that fixes it.
- **Other updates** - packages with a newer release and no security finding.

Each group lists up to four packages and then says how many more there are. A row, or **Open Plugins** at the bottom, takes you to System → Plugins, where each affected row names the security update and its fix. The list itself is only fetched when you open the pill, so the header stays as light as before.

A publisher that cannot be reached never clears a warning. VitNode keeps the last known findings and adds _Based on the last known results_ under the list, so an outage at the publisher never looks like a fix.

## The System updates widget

The **System updates** widget is on the dashboard by default for staff who can view plugins. You can remove it or add it back from **Edit layout**, like any other widget. It opens with a one-line status and a short explanation, then lists one row per fact, and ends with a **View plugins** link and the time of the last check.

| Row            | Meaning                                                                                                   |
| -------------- | --------------------------------------------------------------------------------------------------------- |
| VitNode        | The core version you run and, after the arrow, the newer core release on your channel when one is known. |
| Plugin updates | Plugins with a newer release on their channel, as _N available_ or _None_. Core is not included here.     |
| Security fixes | How many packages, core included, a security update affects (_Needed for N packages_), or _None found_.  |
| No update info | How many packages, out of all, publish no update info. The row appears only when some do.                |

Before anything was checked, the rows show _Unknown_ instead of a number.

### Status

| Status                  | What it means                                                                                         |
| ----------------------- | ----------------------------------------------------------------------------------------------------- |
| Security fix needed     | At least one package you run is affected by a security update.                                        |
| Updates available       | A newer release exists for core or a plugin, and nothing is affected by a security update.            |
| Everything is up to date | Every installed package was checked and none has an update or a security warning.                    |
| No updates found        | Nothing is outdated, but some packages publish no update info, so VitNode cannot check them. The explanation says how many were confirmed. |
| Checking for updates... | A check is running. The widget, the count and the pill refresh every 15 seconds until it finishes.    |
| Not checked yet         | No check has run. The daily check runs overnight, or press **Check for updates** on the Plugins page. |
| Can't check for updates | No installed package publishes update info.                                                           |
| Update checks are off   | The API config sets `updates.enabled` to `false`.                                                     |

### Last check

The line at the bottom right says how fresh the numbers are:

| Text                                | What it means                                                                                                           |
| ----------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| Checked _date_                      | The oldest stored result is from that date, so every package was checked at least that recently.                        |
| Last check failed _date_            | The latest check could not read a source. The numbers include the last known results for it.                            |
| Checked _date_, needs a recheck     | You redeployed, upgraded core or changed channel. Results are recomputed from the stored manifests until the next check. |
| Checking now...                     | A check is running.                                                                                                      |
| Never checked                       | Nothing has been checked yet.                                                                                           |

The date is the **oldest** successful result, not the newest. One package checked a minute ago does not prove the others were.

## When update checks are turned off

With `updates: { enabled: false }` in the API config, nothing is checked. The navigation count and the security pill stay hidden, and the widget only says that checks are turned off. Nothing stored earlier is shown as current.

## How fresh the alerts are

The alerts share one request per browser tab. It is refreshed when it is older than a minute and you come back to the tab, after **Check for updates** finishes, and every 15 seconds while a check is running. There is no other polling.

## Check the result

Press **Check for updates** on **System → Plugins**. When it finishes, the count next to **Plugins**, the security pill and the widget update together without reloading the page.
