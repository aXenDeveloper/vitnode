## Before you begin

- A [cron adapter or external trigger](/docs/dev/cron) must be running. The daily check is a cron job; without a scheduler nothing is checked automatically.
- The API server needs outbound HTTPS (port 443) to the update manifests - for VitNode itself, `raw.githubusercontent.com`. Requests go out directly; HTTP proxy variables such as `HTTPS_PROXY` are not used.
- Run `vitnode db migrate` after upgrading. The check stores its results in three small tables: `core_update_sources`, `core_update_results` and `core_update_lock`.

## The daily check

The cron job `@vitnode/core:cron:check_updates` runs at **03:17 every day in the API server's time zone** (the `TZ` environment variable - UTC on most hosts and containers). A newly registered job has never run, so the first scheduler tick after you deploy runs the first check. Until then every row says _Not checked yet_.

Each run fetches every distinct manifest once, even when several plugins share it, with a 10 second timeout, a 1 MB size limit and at most four sources at a time. Opening the catalog never contacts a publisher - it only reads stored results.

## Check now

Staff with **Plugins → Check for plugin and core updates now** (`plugins.can_check_updates`) see a **Check for updates** button. It runs the same check as the cron job and refreshes the page when it finishes.

- Only one check runs at a time across all API instances. A second click while one runs says _A check is already running_.
- A manual check can run once every two minutes. A click inside that window says how many seconds to wait.
- The endpoint is `POST /api/@vitnode/core/admin/plugins/updates/check`; it answers `409` while a check runs and `429` during the cooldown.

Viewing the results only needs **Plugins → View installed plugins and their versions** (`plugins.can_view`).

## Read the results

| Status                              | What it means                                                                                                                                              |
| ----------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Not checked yet                     | No check has covered this package yet.                                                                                                                     |
| Up to date                          | Every version you run is at or above the channel's newest release.                                                                                         |
| Update available: 2.1.3             | A newer release is on your channel. Release notes link to it when the publisher gave one.                                                                  |
| Requires a newer core               | The release declares a core range your core is outside. If an older release on the channel fits, it is named.                                              |
| Compatibility unknown               | The publisher did not say which core the release needs. VitNode does not guess.                                                                            |
| Update checking unavailable         | The package declares no update source.                                                                                                                     |
| Last check failed                   | The source could not be read. The last good result stays visible, with its date.                                                                           |
| Not checked for this deployment yet | You redeployed, changed channel or upgraded core since the last check. Results are recomputed from the stored manifest until the next check confirms them. |

When the web app and the API run different versions of a plugin, the existing mismatch warning stays, and both versions are checked. A vulnerable web app version is reported even if the API's version is fine.

## Security warnings

A red **Security update** box with a shield icon appears when a version you run is inside a security update's affected range. It names the security update, the affected version - with _(API)_ or _(web app)_ when they differ - and either _Fixed in 2.1.3_ or _No fixed version has been published yet_. **Details** opens the publisher's page.

Security updates are checked even when your channel has no newer release. A patch release on its own is never shown as a security fix; only a matching security update is.

## Choose a channel

By default each package follows the channel of the version you run: `2.1.0` is **stable**, `2.1.0-rc.1` is **rc** and `2.1.0-canary.4` is **canary**. VitNode never moves you between channels or suggests a downgrade. To follow another channel on purpose, set it in the API config:

```ts title="src/vitnode.api.config.ts"
export const vitNodeApiConfig = buildApiConfig({
  updates: {
    channel: 'stable',
  },
  // ...the rest of your API config
})
```

An install without outbound network access can switch checks off with `updates: { enabled: false }`. The catalog then says so instead of showing results.

## Check the result

Open **System → Plugins** and press **Check for updates**. A toast reports how many updates and security updates were found, and the core card shows _Last checked_ with the current time.
