title: Users
description: Helper functions and components to work with users.
---

VitNode ships with a small set of helpers for reading the currently authenticated user and for looking users up by their `id` or `nameCode`. Backend helpers run inside your API route handlers (Hono context); frontend helpers are TanStack Query definitions and components.

## Backend

### Current user

The global middleware resolves the session cookie on every request and exposes the authenticated user through the Hono context. Read it with `c.get("user")` inside any route handler - it returns the user object, or `null` for guests.

```ts title="plugins/{plugin_name}/src/api/routes/me.route.ts"
import { buildRoute } from "@vitnode/core/api/lib/route";

export const meRoute = buildRoute({
  handler: async c => {
    const user = c.get("user");

    if (!user) {
      return c.json({ message: "Not signed in" }, 401);
    }

    return c.json({ user });
  },
});
```

The user object has the following shape:

```ts
{
  id: number;
  email: string;
  name: string;
  nameCode: string;
  avatarColor: string;
  newsletter: boolean;
  emailVerified: boolean;
  roleId: number;
  birthday: Date | null;
  createdAt: Date;
}
```

<Callout type="info" title="Roles">
  `roleId` points to the role the user belongs to. See
  [Roles](/docs/dev/working-with-users/roles) for more.
</Callout>

### Looking up a user

Use the `UserModel` when you need to fetch a user that is **not** the one making the request. It exposes `getUserById` and `getUserByNameCode`, both of which return the user, or `null` when no match is found.

```ts title="plugins/{plugin_name}/src/api/routes/user.route.ts"
import { buildRoute } from "@vitnode/core/api/lib/route";
import { UserModel } from "@vitnode/core/api/models/user";

export const userRoute = buildRoute({
  handler: async c => {
    const user = await new UserModel().getUserById({ id: 3, c });
    // or: getUserByNameCode({ nameCode: "john_doe", c })

    if (!user) {
      return c.json({ message: "User not found" }, 404);
    }

    return c.json({ user });
  },
});
```

## Frontend

### Current session

The session is one TanStack Query entry, and everything reads it through the same
options object. In a route's `loader`, warm it:

```tsx title="apps/web/src/routes/_main/profile.tsx"
import { createFileRoute } from "@tanstack/react-router";
import { sessionQueryOptions } from "@vitnode/core/tanstack/auth";

export const Route = createFileRoute("/_main/profile")({
  loader: async ({ context }) =>
    await context.queryClient.ensureQueryData(sessionQueryOptions()),
  component: ProfileRoute,
});
```

and in a component, read the identical entry back:

```tsx
import { useQuery } from "@tanstack/react-query";
import { sessionQueryOptions } from "@vitnode/core/tanstack/auth";

const ProfileRoute = () => {
  const { data } = useQuery(sessionQueryOptions());

  if (!data?.user) return <p>You are not signed in.</p>;

  return <p>Welcome back, {data.user.name}!</p>;
};
```

`data` is `{ user }`, where `user` is the authenticated user - including an
`isAdmin` flag - or `null` for guests. To type a component that receives the user
as a prop, use the exported `SessionApi` type:

```tsx title="profile.tsx"
import type { SessionApi } from "@vitnode/core/tanstack/auth";

export const Profile = ({
  user,
}: {
  user: NonNullable<SessionApi["user"]>;
}) => <span>{user.name}</span>;
```

<Callout type="warn" title="The key addresses a cache; it never authorizes anything">
  Who the session belongs to is decided in Hono, from the cookie, on every
  request. And because the browser's `QueryClient` outlives a sign-out, any
  *other* private read you cache must be partitioned by the owner's id - see
  [Cache](/docs/dev/cache).
</Callout>

### Current admin session

Admin pages have their own session, separate from the public one, under its own
cookie. It works the same way, through `adminSessionQueryOptions()` from
`@vitnode/core/tanstack/admin` - the `_admin` shell's guard warms it before any
admin route renders, so a screen inside the AdminCP just reads it:

```tsx
import { useSuspenseQuery } from "@tanstack/react-query";
import { adminSessionQueryOptions } from "@vitnode/core/tanstack/admin";

const AdminHome = () => {
  const { data } = useSuspenseQuery(adminSessionQueryOptions());

  return <p>Signed in as {data.user.name}</p>;
};
```

<Callout type="warn" title="The guard is navigation, not security">
  The shell's guard decides whether to *show* a screen. Every admin route and
  action behind it re-checks the staff tables on the server, on every request.
  See [Staff permissions](/docs/dev/working-with-users/staff-permissions).
</Callout>

### Avatar

Render a user's avatar with the `Avatar` component. It generates a letter avatar from the user's `name` and `avatarColor`.

```tsx title="user-card.tsx"
import { Avatar } from "@vitnode/core/components/avatar";

<Avatar size={24} user={user} />;
```

The `user` prop requires `name`, `nameCode`, and `avatarColor`, and `size` sets the avatar's width and height in pixels.

### Formatting a user

Use the `UserFormat` component to render a user's nickname together with their role. Pass the `format` prop to color the nickname with the role's `color`.

```tsx title="user-link.tsx"
import { UserFormat } from "@vitnode/core/components/user-format";

<UserFormat
  format
  user={{
    id: 1,
    name: "John Doe",
    nameCode: "john_doe",
    role: {
      id: 2,
      name: "Administrator",
      color: "#ef4444",
    },
  }}
/>;
```

The `user` prop has the following shape:

```ts
{
  id: number;
  name: string;
  nameCode: string;
  role: {
    id: number;
    name: string;
    color: string | null;
  }
}
```

| Prop     | Description                                             |
| -------- | ------------------------------------------------------- |
| `user`   | The user to render, including their `role`.             |
| `format` | When set, colors the nickname using the role's `color`. |

<Callout type="info" title="Roles">
  To render a role on its own, use the
  [`RoleFormatContent`](/docs/dev/working-with-users/roles#formatting-a-role)
  component.
</Callout>
