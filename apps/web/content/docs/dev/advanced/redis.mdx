[Redis](https://redis.io) serves as VitNode's shared cache and pub/sub broker across horizontally scaled instances. Redis is optional: without it, VitNode degrades gracefully to in-memory counters and local delivery.

## Quick start

### 1. Configure Environment Variables

```bash title=".env"
REDIS_URL=redis://localhost:6379 // [!code ++]
REDIS_PASSWORD=root // [!code ++]
```

### 2. Connect in API Configuration

```ts title="apps/api/src/vitnode.api.config.ts"
import { buildApiConfig } from "@vitnode/core/vitnode.config"

export const vitNodeApiConfig = buildApiConfig({
  // [!code ++:5]
  redis: process.env.REDIS_URL
    ? { url: process.env.REDIS_URL, password: process.env.REDIS_PASSWORD }
    : undefined,
})
```

## What Redis Powers

| Feature | Without Redis | With Redis |
| :--- | :--- | :--- |
| **API Domain Cache** | No-op (always executes DB query) | Shared key-value store via `c.get("cache")` |
| **Rate Limiter** | In-memory counters per instance | Distributed sliding-window across cluster |
| **WebSocket Realtime** | Single instance only | Cross-instance delivery via Redis Pub/Sub; required on serverless hosts ([details](/docs/dev/websocket/reconnects#delivery-across-instances)) |
| **Sessions** | Database queries on every request | Instant cache hits with DB fallback |

## Local Development (Docker)

Start a Redis container with Docker Compose:

```yaml title="docker-compose.yml"
services:
  redis:
    image: redis:7-alpine
    restart: always
    ports:
      - "6379:6379"
    command: redis-server --requirepass root
```

---

## Using the Cache in API Routes

Use `remember` with a key, a TTL in seconds, and a loader to cache expensive database lookups:

```ts
const posts = await c.get("cache").remember(
  "featured_posts",
  60,
  async () => await fetchFeaturedPostsFromDB(),
)
```

See [Cache API data](/docs/dev/cache/api) for invalidation and the full method list.

## Check Redis in the AdminCP

{/* Image prompt: VitNode AdminCP Debug Panel at /admin/core/debug/cache with the "Cache" section open. Engine "Redis" with a green "Redis connected" status, "Realtime across instances: Yes", and a "Clear cache" button. Dark theme, 1440x900. */}

Open **Debug Panel → Cache** in the AdminCP (`/admin/core/debug/cache`). It shows whether Redis is connected, unreachable or not configured (then the cache lives in memory), and whether realtime events reach every instance. An unreachable Redis also shows up on the Debug Panel's **Overview**.
