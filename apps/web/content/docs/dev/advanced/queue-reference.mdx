## `dispatch()`

`c.get("queue").dispatch()` has two overloads. Both resolve to `{ deduplicated: boolean; id: number | null }` and only insert a row.

```ts
dispatch(task: QueueTaskDefinition, payload: QueueTaskInput<typeof task>, options?: QueueDispatchOptions)
dispatch(args: QueueDispatchArgs)
```

| Overload                                     | Identity                                                                 | Payload check                                                                                                                          |
| -------------------------------------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------- |
| `dispatch(task, payload, options)`           | The definition's `pluginId` and `name`; the options cannot override them | Compile time against the schema input, then runtime validation. Throws when the task is not registered or another task holds its name. |
| `dispatch({ name, payload, pluginId, ... })` | `pluginId`, else the current route's plugin, else `@vitnode/core`        | Runtime validation only, and only when the registered task has a schema. A name with no registered task is still queued.    |

## Types

All from `@vitnode/core/api/lib/queue`, except `QueueDispatchOptions` and `QueueDispatchResult` from `@vitnode/core/api/models/queue`.

| Type                                        | Meaning                                                     |
| ------------------------------------------- | ----------------------------------------------------------- |
| `QueueTaskDefinition<Plugin, Name, Schema>` | A typed task, as the bound builder returns it.              |
| `QueueTaskInput<typeof task>`               | What `dispatch(task, payload)` accepts: the schema's input. |
| `QueueTaskPayload<typeof task>`             | What the handler receives: the schema's output.             |
| `QueueDispatchOptions`                      | The third argument of the typed `dispatch`.                 |
| `QueueDispatchResult`                       | `{ deduplicated, id }`.                                     |

Input and output differ when the schema transforms. With `at: z.iso.datetime().transform(value => new Date(value))`, `dispatch` takes a string and the handler gets a `Date`.

## JSON payloads

A payload is stored as JSON in `core_queue.payload` and parsed back for the handler. Before validating, `dispatch` copies the payload to JSON and throws `QueuePayloadValidationError` instead of letting `JSON.stringify` change it:

- **Rejected:** `Date`, `Map`, `Set` and other class instances, `NaN`, `Infinity`, `bigint`, functions, circular references, and `undefined` or missing (sparse) array items.
- **Omitted:** object properties set to `undefined`, exactly as JSON drops them. Make such fields `.optional()`.
- **Stored:** the JSON input, never the schema's output. The worker parses it again, so a transform runs on every attempt and stored rows stay readable after a transform changes.

The schema's input type must be JSON, so `z.date()` or `z.map()` in a payload schema is a compile error. Use `z.iso.datetime()`, optionally with a `.transform()`.

## Errors

| Error                         | Thrown by             | When                                                                                                       | Enqueued |
| ----------------------------- | --------------------- | ---------------------------------------------------------------------------------------------------------- | -------- |
| `QueuePayloadValidationError` | `dispatch`            | The payload is not JSON, or the schema rejects it. `reason` lists paths and issue codes, never values.     | No       |
| `QueueTaskRegistrationError`  | `dispatch(task, ...)` | The task is not registered, or a different task is registered under its name.                              | No       |
| `QueueTaskRegistrationError`  | `buildApiPlugin`      | A typed task is registered by another plugin, or shares its name with a different task of the same plugin. | -        |

When the worker finds a stored payload its task's schema rejects, the row becomes **failed** at once with `Invalid payload: …` in `lastError`; it is not retried and is kept. A row whose task is not registered is retried with `No handler registered for queue task "…"` until it runs out of attempts.
