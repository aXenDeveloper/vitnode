Add a **Continue with Atlassian** button so people can sign in with the Atlassian account they use for Jira, Confluence or Trello. This is sign-in only: VitNode asks for the person's own profile and nothing from Jira, Confluence or any other product.

## Quick start

```bash title=".env"
ATLASSIAN_CLIENT_ID=AbCdEf123456
ATLASSIAN_CLIENT_SECRET=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

```ts title="src/vitnode.api.config.ts"
import { AtlassianSSOApiPlugin } from '@vitnode/core/api/adapters/sso/atlassian' // [!code ++]
import { buildApiConfig } from '@vitnode/core/vitnode.config'

export const vitNodeApiConfig = buildApiConfig({
  plugins: [],
  // [!code ++:8]
  authorization: {
    ssoAdapters: [
      AtlassianSSOApiPlugin({
        clientId: process.env.ATLASSIAN_CLIENT_ID,
        clientSecret: process.env.ATLASSIAN_CLIENT_SECRET,
      }),
    ],
  },
})
```

## Set up the integration

<Steps>
<Step>

### Create an OAuth 2.0 integration

Open the [Atlassian developer console](https://developer.atlassian.com/console/myapps/), press **Create** and choose **OAuth 2.0 integration**. Name it after your site - people see the name on the consent screen.

</Step>

<Step>

### Add only the User identity API

Open **Permissions**, find **User identity API** and press **Add**, then **Configure** and enable **View user profile** (`read:me`). Leave every product API (Jira, Confluence, Bitbucket) alone - VitNode does not need them, and asking for them would turn a sign-in button into a product integration.

</Step>

<Step>

### Add the callback URL

Open **Authorization**, press **Add** next to **OAuth 2.0 (3LO)** and enter the callback URL:

| Environment                           | Callback URL                                  |
| ------------------------------------- | --------------------------------------------- |
| Development (`VITNODE_WEB_URL` unset) | `http://localhost:3000/login/sso/atlassian`   |
| Production                            | `https://your-domain.com/login/sso/atlassian` |

VitNode builds it from `VITNODE_WEB_URL`, so it must match exactly.

</Step>

<Step>

### Copy the credentials

Open **Settings** and copy the **Client ID** and **Secret** into server-side variables (never `clientEnv`):

```bash title=".env"
ATLASSIAN_CLIENT_ID=AbCdEf123456 # [!code ++]
ATLASSIAN_CLIENT_SECRET=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx # [!code ++]
```

</Step>

<Step>

### Register the adapter and restart

Add `AtlassianSSOApiPlugin` as in the [quick start](#quick-start) and restart the server:

<Tabs groupId='package-manager' persist items={['bun', 'pnpm', 'npm']}>

```bash tab="bun"
bun dev
```

```bash tab="pnpm"
pnpm dev
```

```bash tab="npm"
npm run dev
```

</Tabs>

</Step>

<Step>

### Check the result

Open `/login` and press **Continue with Atlassian**. The consent screen should list only "View your user profile". After **Accept** you return to `/login/sso/atlassian` and are signed in - or asked to [confirm an email](/docs/dev/sso/email-confirmation) if Atlassian did not share a verified one.

</Step>
</Steps>

## Share the integration

A new integration works only for its owner. To let anyone sign in, open **Distribution**, set the status to **Sharing**, and fill in the vendor and privacy details Atlassian asks for.

## Scopes and profile fields

| Setting        | Value                                    |
| -------------- | ---------------------------------------- |
| Scopes         | `read:me`                                |
| Account ID     | `account_id` (one per Atlassian account) |
| Email trusted  | only with `email_verified: true`         |
| Profile fields | avatar                                   |

Atlassian has no separate first and last name, and VitNode does not split the display name. People can hide their email in their Atlassian profile; they then confirm one by email.

## Troubleshooting

- **"Something went wrong" on Atlassian's page** - the callback URL is not on the **Authorization** page, or `VITNODE_WEB_URL` differs from it.
- **Only you can sign in** - the integration is not shared yet; see [Share the integration](#share-the-integration).
- **The consent screen asks for Jira or Confluence** - a product API was added under **Permissions**. Remove it; sign-in needs only `read:me`.
