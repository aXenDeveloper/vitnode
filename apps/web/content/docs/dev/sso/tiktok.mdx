Add a **Continue with TikTok** button using TikTok's Login Kit for Web. The adapter asks only for `user.info.basic`. TikTok never shares an email address, so new members confirm one by email.

## Before you begin

- A running VitNode app. This page covers only the TikTok parts; [SSO setup](/docs/dev/sso#set-up-your-first-provider) explains the shared steps and [where the API's `.env` and config live](/docs/dev/sso#where-the-files-live).
- A [TikTok for Developers](https://developers.tiktok.com/) account.
- A public **HTTPS** redirect URI. TikTok requires an absolute `https://` redirect URI for web apps, with no query string or fragment, so develop through a tunnel (see [Develop locally](#develop-locally)).
- An [email adapter](/docs/dev/email), to send the [confirmation link](/docs/dev/sso/email-confirmation).

## Set up the app

<Steps>
<Step>

### Create an app

In the [TikTok developer portal](https://developers.tiktok.com/apps/), press **Connect an app**, choose an organization or individual owner, and fill in the app name, icon, category, description, terms of service and privacy policy URLs.

</Step>

<Step>

### Add Login Kit and the redirect URI

Under **Products**, add **Login Kit**. In its settings, choose **Web** and add the redirect URI:

| Environment | Redirect URI                                     |
| ----------- | ------------------------------------------------ |
| Production  | `https://your-domain.com/login/sso/tiktok`       |
| Development | `https://forum-dev.example.com/login/sso/tiktok` |

TikTok needs an absolute, static HTTPS URL with no query string. VitNode builds it as `{VITNODE_WEB_URL}/login/sso/tiktok`, so they must match exactly.

</Step>

<Step>

### Check the scope

Under **Scopes**, make sure `user.info.basic` is listed. It is all VitNode needs; leave out `user.info.profile`, `video.list` and the rest.

</Step>

<Step>

### Copy the credentials

Copy the **Client Key** and **Client Secret** from the app's credentials into server-side variables:

```bash title=".env"
TIKTOK_CLIENT_KEY=awxxxxxxxxxxxxxx # [!code ++]
TIKTOK_CLIENT_SECRET=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx # [!code ++]
```

</Step>

<Step>

### Add the adapter

Add `TikTokSSOApiPlugin` to `authorization.ssoAdapters` in the API's `vitnode.api.config.ts` ([where it lives](/docs/dev/sso#where-the-files-live)), next to any adapters you already have. Keep the rest of the config as it is:

```ts title="src/vitnode.api.config.ts (excerpt)"
import { TikTokSSOApiPlugin } from '@vitnode/core/api/adapters/sso/tiktok' // [!code ++]
import { buildApiConfig } from '@vitnode/core/vitnode.config'

export const vitNodeApiConfig = buildApiConfig({
  // ...
  authorization: {
    ssoAdapters: [
      // ...
      // [!code ++:4]
      TikTokSSOApiPlugin({
        clientKey: process.env.TIKTOK_CLIENT_KEY,
        clientSecret: process.env.TIKTOK_CLIENT_SECRET,
      }),
    ],
  },
})
```

No `authorization` block yet? Create one with just `ssoAdapters`, as in the [SSO setup](/docs/dev/sso#add-the-adapter-to-ssoadapters). Then restart the dev server, since `.env` and the API config are only read at start-up.

</Step>

<Step>

### Check the result

Open `/login` on your HTTPS domain, press the **TikTok** button under **Continue with** and authorize. The first time, VitNode asks for an email and sends a confirmation link. Open it in the same browser. After that, the same TikTok account signs straight in.

</Step>
</Steps>

## Test in sandbox, then submit for review

A new app cannot be used by the public until TikTok approves it. To test before that, create a **Sandbox** for the app in the developer portal and add up to ten **target users**. Only those TikTok accounts can sign in. Use the credentials shown for the sandbox while you test.

When it works, switch the variables to the production credentials and **Submit for review**. TikTok asks you to explain each product and scope and to upload at least one demo video. For apps created after 9 September 2024, the terms of service, privacy policy and website URLs must first be verified as URL properties in the portal.

## Develop locally

Run the dev server behind an HTTPS tunnel (for example Cloudflare Tunnel or ngrok), add that URL to Login Kit, and set:

```bash title=".env"
VITNODE_WEB_URL=https://forum-dev.example.com
VITNODE_API_URL=https://forum-dev.example.com
```

## Scopes and profile fields

| Setting        | Value                                                         |
| -------------- | ------------------------------------------------------------- |
| Scopes         | `user.info.basic`                                             |
| Account ID     | `open_id` (unique to your app)                                |
| Email          | never shared; [confirmed by email](/docs/dev/sso/email-confirmation) |
| Profile fields | avatar                                                        |

The display name becomes the new account's name. Import the avatar from [Connected accounts](/docs/dev/sso/connected-accounts); VitNode downloads and stores its own copy.

## Troubleshooting

- **"redirect_uri" error on TikTok's page.** The URI in Login Kit differs from `{VITNODE_WEB_URL}/login/sso/tiktok`, or it is not HTTPS.
- **"client_key" error.** You used the sandbox key with production credentials, or the other way round.
- **Only some accounts can sign in.** The app is still in sandbox; add them as target users or submit the app for review.
